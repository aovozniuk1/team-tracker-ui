# Урок 4. Словник і «велика картина»

*У Claude Code постійно звучать кілька слів: модель, промпт, повідомлення, хід, відповідь. Якщо їх
плутати, плутаються й пояснення в кожному наступному уроці. Тут ти вивчиш ці п'ять слів і один
ключовий факт, з якого випливає майже все інше: модель нічого не пам'ятає між викликами. Після уроку
ти малюєш повний цикл роботи Claude Code від твого промпту до відповіді, розпізнаєш його кроки на
екрані й пояснюєш, звідки береться «пам'ять» у розмові.*

## Коротко

*Картка уроку: прочитай її перед уроком і повернись до неї після.*

**Одним реченням.** Ти пишеш промпт, Claude Code додає його до всієї попередньої розмови й надсилає
моделі; модель просить інструмент щось зробити, результат додається до розмови — і так по колу, доки
модель не напише відповідь.

**Навіщо.** Ця картина пояснює, чому розмови «дорожчають» із часом, чому довгі сесії гіршають і
навіщо файли пам'яті, — тобто все, про що йдеться в уроках 5–14.

**Де.** У будь-якій сесії Claude Code: твої повідомлення, рядки викликів інструментів і відповіді
видно прямо в терміналі; подробиці — через `Ctrl+O`.

**Модель**

- **Модель** — «мозок», що пише текст; **Claude Code** — обгортка (harness), що дає моделі
  інструменти, пам'ять і місце для роботи.
- **Промпт** — усе, що ти пишеш Claude.
- **Повідомлення** — один запис у розмові: твій, Claude або результат інструмента.
- **Хід (turn)** — від твого промпту до моменту, коли Claude повертає тобі слово.
- **Відповідь** — те, що Claude пише в кінці ходу.

**Запам'ятай**

1. Модель не пам'ятає нічого між викликами; «пам'ять» — це повторне надсилання всієї історії.
2. Один хід може містити десятки кроків: прочитати файли, змінити, запустити перевірку.
3. Модель сама нічого не робить на комп'ютері — вона просить інструмент, а виконує Claude Code.
4. Результат кожного інструмента теж стає повідомленням у розмові.
5. Нова розмова (`/clear`) — модель знову «чистий аркуш», знає лише те, що є у файлах.

**Пастки** (симптом → причина)

- «Я ж йому вчора казав!» → нова розмова не містить учорашніх повідомлень.
- Коротке питання наприкінці довгої розмови «дороге» → разом із ним надсилається вся історія.
- «Claude змінив файл без мене» → він просив інструмент, і Claude Code виконав його за правилами
  дозволів (урок 9).

**Як перевірити**

- Ти відкриваєш Claude Code, просиш прочитати файл, ставиш уточнювальне питання, робиш `/clear` і
  пояснюєш, чому після `/clear` Claude не знає, про який файл ішлося.

## 4.1. Модель і обгортка

З уроку 1 ти знаєш: **модель** — це «мозок», величезна програма, навчена на тексті, яка передбачає,
що написати далі. Моделі Claude бувають різні — Fable, Opus, Sonnet, Haiku: сильніші повільніші й
дорожчі за кожен токен, легші — швидші й дешевші.

Сама по собі модель уміє лише одне: отримати текст і написати текст. Вона не бачить твого диска, не
відкриває файли, не запускає команди.

**Claude Code** — це **обгортка** навколо моделі (в англомовній документації — *harness*, буквально
«упряж»): програма, яка дає моделі **інструменти**, **пам'ять** і **місце для роботи**.

| хто | що робить | аналогія |
|---|---|---|
| модель | думає й пише текст, зокрема «прохання» виконати дію | досвідчений майстер, який диктує по телефону |
| Claude Code | надсилає моделі розмову, виконує її прохання, повертає результат | помічник на місці, який тримає інструменти й робить, що продиктовано, — у межах дозволеного |

Через цю пару в документації пишуть то «Claude прочитав файл», то «Claude Code виконав команду». І
те, і те правда: вирішує модель, а виконує обгортка.

⏸ **Зупинись і перевір себе.** Хто фізично відкриває файл на твоєму комп'ютері — модель чи Claude
Code?

> **Відповідь.** Claude Code. Модель лише просить: «прочитай цей файл». Claude Code перевіряє
> дозволи, читає файл і передає його вміст моделі.

## 4.2. Промпт

**Промпт** (*prompt*) — усе, що ти пишеш Claude. «Виправ баг у формі входу» — промпт. Тристорінкова
специфікація — теж промпт. Одне слово «далі» — і це промпт.

> Не плутай із запрошенням терміналу з уроку 2: англійською воно теж *prompt*. У Claude Code
> «промпт» — це саме твоє повідомлення для Claude.

*Приклади промптів (ілюстративні):*

```
Що лежить у цій папці?
```

```
Прочитай bug-report.txt і перепиши кроки відтворення нумерованим списком.
Нічого не вигадуй: якщо кроку бракує, познач його як [НЕВІДОМО].
```

Перший — короткий і загальний, другий — конкретний: файл, дія, формат, обмеження. Чіткі, конкретні
промпти дають кращий результат; як їх писати — уроки 12–13.

Не все, що ти набираєш у полі вводу, — звичайний промпт. Рядок, який починається з `/`, — це
**команда** Claude Code (як `/login` з уроку 3 чи `/clear` нижче). Такі команди, як `/login` чи
`/clear`, виконує сама програма, а модель їх навіть не бачить. Є й команди, що передають моделі
заготовлену інструкцію, — про них в уроці 16.

⏸ **Зупинись і перевір себе.** Що з цього промпт, а що команда: `/clear`, `поясни цей лог`,
`/logout`, `так, продовжуй`?

> **Відповідь.** Команди — `/clear` і `/logout` (починаються з `/`, їх виконує сама програма).
> Промпти — `поясни цей лог` і `так, продовжуй` (їх отримує модель).

## 4.3. Повідомлення

**Повідомлення** (*message*) — один запис у розмові. Їх є три види:

| вид | хто «автор» | приклад |
|---|---|---|
| **повідомлення користувача** (*user message*) | ти | «Чому падає `npm test`?» |
| **повідомлення асистента** (*assistant message*) | модель | «Зараз запущу тести й подивлюся на помилку» + прохання запустити команду |
| **результат інструмента** (*tool result*) | Claude Code | вміст відкритого файлу, вивід команди |

Найважливіше в цій таблиці — третій рядок. Коли Claude читає файл, **прочитаний вміст** стає
повідомленням у розмові. Коли запускає команду, **її вивід** — теж. Тобто розмова складається
не лише з того, що ви з Claude сказали одне одному, а й з усього, що Claude прочитав і побачив.

*Приклад.* Ти пишеш одне речення «Що в файлі `app.log`?». Claude читає файл на 300 рядків. Тепер
у розмові три повідомлення: твоє речення, прохання Claude прочитати файл, і результат — 300
рядків логу. Найбільше з них — зовсім не твоє.

⏸ **Зупинись і перевір себе.** Ти попросив Claude прочитати два файли й відповісти. Скільки
повідомлень щонайменше додалося до розмови і які?

> **Відповідь.** Щонайменше п'ять: твій промпт; прохання Claude прочитати перший файл і його
> результат (вміст файлу); прохання прочитати другий файл і його результат. Плюс фінальна відповідь
> Claude — шосте. (Якщо Claude попросить обидва файли одним проханням, прохань буде одне, а
> результатів однаково два.)

## 4.4. Хід

**Хід** (*turn*) — один раунд: ти надсилаєш промпт, а Claude працює, доки не зупиниться й не поверне
тобі слово. В одному ході може бути **десятки кроків**: Claude може прочитати десять файлів, змінити
три й двічі запустити тести, перш ніж відповісти.

*Приклад одного ходу (ілюстративний).* Ти пишеш: «Чому падає `npm test`?» Усередині одного ходу
Claude може:

1. Запустити `npm test` і прочитати помилку.
2. Відкрити `src/math.js` — файл, названий у помилці.
3. Помітити, що функція `add()` повертає текст замість числа.
4. Змінити файл, щоб виправити це.
5. Знову запустити `npm test` — тепер усе проходить.
6. Відповісти: «Тест падав, бо `add()` склеювала числа як текст. Я перетворив їх на числа; усі
   42 тести проходять».

На цьому хід закінчується, і знову твоя черга.

Ще одне корисне слово — **крок** (*step*): одне звернення до моделі всередині ходу. У прикладі
вище модель «думала» кілька разів: перед запуском тестів, після помилки, після читання файлу, після
зміни, після повторного запуску. Кожне таке «подумати» — окремий крок.

Аналогія: хід — це одне доручення майстрові («полагодь кран»). Кроки — усе, що він робить, поки не
скаже «готово»: подивився, перекрив воду, замінив прокладку, перевірив.

⏸ **Зупинись і перевір себе.** Скільки ходів у такій розмові: ти пишеш «знайди помилку в
`app.log`», Claude відкриває файл, шукає, відповідає; ти пишеш «а що було перед нею?», Claude
відповідає?

> **Відповідь.** Два ходи: кожен твій промпт починає новий хід, і кожен закінчується відповіддю
> Claude. Кількість кроків усередині ходів може бути різною.

---

## 4.5. Відповідь

**Відповідь** (*response*) — те, що Claude пише наприкінці ходу: зазвичай підсумок того, що він
зробив, що знайшов, або питання до тебе.

Зверни увагу: відповідь — це **слова моделі про роботу**, а не сама робота. Підсумок «усі 42 тести
проходять» — твердження. Доказ — у результатах інструментів усередині ходу (вивід `npm test`). З
уроку 1 ти пам'ятаєш, що модель може помилятися впевненим тоном, тож важливі твердження перевіряй:
розгорни подробиці виклику (розділ 4.8) або запусти перевірку сам.

Інколи відповідь — це питання: «Знайшов два способи виправити. Який обрати?» Тоді хід закінчився
не результатом, а запитом до тебе, і Claude чекає.

⏸ **Зупинись і перевір себе.** Чим відповідь «я запустив тести, усе зелене» відрізняється від
виводу команди тестів?

> **Відповідь.** Відповідь — це підсумок, написаний моделлю; він може бути неточним. Вивід
> команди — справжній результат інструмента. Для перевірки дивляться на вивід.

---

## 4.6. Ключовий факт: модель не має пам'яті між викликами

Ось факт, на якому тримається весь курс. **Модель нічого не пам'ятає сама.** Кожного разу, коли
Claude робить крок, Claude Code надсилає моделі **всю розмову від початку**: твої повідомлення, її
відповіді, кожен прочитаний файл, кожен вивід команди. Модель читає все це, вирішує наступний крок —
і забуває. Ілюзія пам'яті виникає тому, що історію надсилають щоразу заново.

Офіційне формулювання:

> "The model doesn't remember anything between requests, so Claude Code re-sends the full context:
> the system prompt, your project context, every prior message and tool result, and your new
> message."

Тобто разом із твоїм новим повідомленням щоразу надсилаються:

- **системний промпт** (*system prompt*) — вбудовані інструкції Claude Code: як користуватися
  інструментами, правила безпеки, оформлення; ти їх не бачиш, але вони там завжди;
- **контекст проєкту** — наприклад, твої файли з інструкціями для Claude (урок 14);
- **кожне попереднє повідомлення і результат інструмента**;
- **твоє нове повідомлення**.

А з документації про пам'ять: "Each Claude Code session begins with a fresh context window." —
кожна сесія Claude Code починається з чистого «робочого столу».

*Аналогія.* Уяви консультанта, який після кожної фрази повністю втрачає пам'ять. Щоб він міг
працювати, помічник щоразу кладе перед ним усю папку справи — від першої сторінки до щойно
доданої. Консультант прочитує її за секунду, пише наступну дію — і забуває. Папка справи — це
розмова, помічник — Claude Code.

### Що з цього випливає (і де про це далі)

| наслідок | чому | урок |
|---|---|---|
| розмова «дорожчає» з кожним кроком | щоразу надсилається вся історія, і вона росте | 5 (токени) |
| довга розмова зрештою заповнює «робочий стіл» моделі | у моделі є межа, скільки тексту вона бачить одночасно | 6 (контекст) |
| довгі сесії працюють повільніше | більше тексту читати на кожному кроці | 6 |
| нова розмова нічого не знає про стару | старі повідомлення в неї не надсилаються | 7 (сесії) |
| потрібні файли на кшталт `CLAUDE.md` | лише так щось переходить між розмовами | 14 (пам'ять) |

Усе, що Claude бачить у цю мить, називається **контекстом** (*context*), а його максимальний розмір
— **контекстним вікном**. Що не потрапило в контекст, того для Claude в цю мить не існує. Докладно
— урок 6.

⏸ **Зупинись і перевір себе.** У довгій розмові ти пишеш одне слово «дякую». Скільки тексту отримає
модель на цьому кроці?

> **Відповідь.** Не одне слово, а всю розмову від початку: системний промпт, контекст проєкту, усі
> попередні повідомлення й результати інструментів — і в кінці «дякую».

## 4.7. Велика картина: цикл роботи

Тепер склади все разом. Твій промпт приєднується до контексту; модель читає весь контекст і просить
інструмент щось зробити; результат додається назад у контекст — і так по колу, доки модель не
напише відповідь:

```
  ти пишеш промпт
        │
        ▼
  ┌─────────────────────────┐
  │ КОНТЕКСТ: системний     │
  │ промпт + уся розмова +  │◄────────────────────┐
  │ твій новий промпт       │                     │
  └────────────┬────────────┘                     │
               ▼                                  │
        МОДЕЛЬ читає все                          │
               │                                  │
     ┌─────────┴──────────┐                       │
     ▼                    ▼                       │
  потрібна дія?      мета досягнута?              │
  просить            пише ВІДПОВІДЬ               │
  ІНСТРУМЕНТ         → хід закінчено,             │
     │               твоя черга                   │
     ▼                                            │
  Claude Code перевіряє дозволи                   │
  і виконує інструмент                            │
     │                                            │
     ▼                                            │
  РЕЗУЛЬТАТ (вміст файлу, вивід команди) ─────────┘
```

**Інструмент** (*tool*) — дія, яку Claude Code дозволяє моделі виконати: прочитати файл, змінити
файл, запустити команду, пошукати в інтернеті. Модель не торкається комп'ютера напряму: вона просить
Claude Code запустити інструмент, Claude Code запускає його (після перевірки дозволів), і результат
повертається в контекст. Повний перелік інструментів — урок 8, дозволи — урок 9.

Документація описує цей цикл трьома фазами: "When you give Claude a task, it works through three
phases: gather context, take action, and verify results. These phases blend together." Тобто:

1. **Зібрати контекст** — прочитати файли, пошукати, подивитися навколо.
2. **Діяти** — змінити файл або запустити команду.
3. **Перевірити результат** — запустити тести, прочитати вивід.
4. **Повторювати**, доки мета не досягнута, — і тоді відповісти тобі.

Фази «змішуються»: перевірка може показати помилку, і Claude знову збирає контекст і діє. Саме тому
так важливо дати Claude **спосіб перевірити** свою роботу: без перевірки циклу нема на чому
помітити помилку.

### Субагенти — одним абзацом

Інколи Claude доручає частину роботи **субагенту** — помічникові, який працює у **власному**
контексті, без твоєї розмови, і повертає лише короткий підсумок. Так велике дослідження не
захаращує основну розмову. На картинці це виглядає як ще один інструмент, результатом якого є
підсумок. Докладно — урок 15.

⏸ **Зупинись і перевір себе.** Простеж цикл для промпту «скільки рядків у `notes.txt`?»: що
відбувається на кожному кроці?

> **Відповідь.** Промпт додається до контексту → модель читає контекст і просить інструмент
> прочитати `notes.txt` → Claude Code перевіряє дозволи (читання в робочій папці дозволене) і читає
> файл → вміст файлу додається в контекст → модель знову читає все, бачить вміст, рахує рядки й
> пише відповідь → хід закінчено.

## 4.8. Як це виглядає на екрані

У сесії Claude Code ти бачиш саме ці частини циклу:

- **твій промпт** — те, що ти набрав;
- **рядки викликів інструментів** — короткі рядки на кшталт «Read src/app.js» чи «Bash: npm test»
  (точний вигляд залежить від версії й системи);
- **відповідь Claude** — текст наприкінці ходу.

Рядок виклику показує, **що** було зроблено, але не весь результат. Щоб побачити подробиці:

- **У терміналі** клацати по рядках не можна. Натисни `Ctrl+O` — це вмикає перегляд розмови, який,
  за документацією, "Shows detailed tool usage and execution", тобто показує докладно, які
  інструменти викликано і що вони повернули. Ще раз `Ctrl+O` — повернення назад.
- **У застосунку для комп'ютера чи у VS Code** рядок виклику можна просто розгорнути кліком.

Коли варто заглядати в подробиці: щоразу, коли Claude стверджує щось важливе («тести пройшли»,
«помилки в логах немає»). Справжній вивід там.

⏸ **Зупинись і перевір себе.** Claude відповів «у файлі 4 рядки». Як у терміналі переконатися, що
він справді читав файл, а не вгадав?

> **Відповідь.** Знайти над відповіддю рядок виклику інструмента читання цього файлу, а для
> подробиць натиснути `Ctrl+O` і подивитися, що саме повернув інструмент.

## 4.10. У роботі QA

- **Логи — це повідомлення.** Попросив Claude прочитати великий лог — усе прочитане стало
  частиною розмови й надсилається на кожному наступному кроці. Краще вказати, що саме шукати:
  «знайди першу помилку після 14:00 у `logs/app.log`».
- **Доказ у результаті інструмента.** У баг-репорт чи звіт про перевірку береш не підсумок Claude,
  а справжній вивід команди з подробиць виклику (`Ctrl+O`).
- **Одна задача — одна розмова.** Перевірив форму входу, тепер треба тест-кейси для кошика — починаєш
  нову розмову (`/clear`), бо стара історія лише заважає й коштує.
- **Правила — у файл.** «Тест-кейси завжди у форматі Назва / Кроки / Очікуваний результат» пишеш у
  файл інструкцій проєкту (урок 14), а не повторюєш щоранку: нова розмова старої не пам'ятає.
- **Цикл перевірки.** Даєш Claude спосіб перевірити роботу: «готово, коли сторінка відкривається
  без помилок у консолі» — тоді цикл «діяти → перевірити» сам ловить частину помилок.

## 4.11. Типові помилки

### Симптом → причина

| симптом | причина | що зробити |
|---|---|---|
| Claude «забув» учорашню домовленість | нова розмова не містить старих повідомлень | запиши домовленість у файл (урок 14) або продовж стару сесію (урок 7) |
| після `/clear` Claude не знає, про що йшлося | `/clear` починає нову розмову з чистим контекстом | так і задумано; потрібне — дай знову або тримай у файлі |
| коротке питання в довгій розмові працює повільно | на кожному кроці модель читає всю історію | нова задача — нова розмова |
| віриш підсумку «усе пройшло» | відповідь — слова моделі, не доказ | дивись вивід інструмента через `Ctrl+O` |
| плутаєш `/clear` із промптом «забудь усе» | `/clear` виконує програма; «забудь» — лише прохання до моделі, історія лишається | для чистого старту — `/clear` |
| думаєш, що модель сама відкриває файли | модель лише просить; виконує Claude Code за правилами дозволів | читай рядки викликів інструментів |
| вставляєш весь лог у промпт | лог стає величезним повідомленням у кожному надсиланні | вкажи шлях до файлу й що в ньому шукати |

## 4.12. Що варто запам'ятати

1. Модель — «мозок»; Claude Code — обгортка з інструментами, пам'яттю й робочою папкою.
2. Промпт — твій текст для моделі; рядок із `/` — команда Claude Code (`/clear` виконує сама програма).
3. Повідомлення бувають трьох видів: твоє, моделі й результат інструмента.
4. Хід — від твого промпту до відповіді; у ньому багато кроків.
5. Відповідь — слова моделі; доказ — у результатах інструментів.
6. Модель не пам'ятає нічого між викликами: Claude Code щоразу надсилає всю розмову.
7. Цикл: промпт → контекст → модель → інструмент → результат → … → відповідь.
8. Три фази: зібрати контекст, діяти, перевірити; без перевірки циклу нема на чому ловити помилки.
9. Нова розмова — чистий аркуш; переносити знання між розмовами можна лише через файли.

# Розв'язки

**4.1.** Зразок: «Модель — як перекладач-синхроніст у навушниках: блискуче говорить, але сам нічого

**4.3.** Команди: `/login`, `/clear`, `/logout` (починаються з `/`, їх виконує сама програма).
Промпти: `покажи останню помилку`, `ок, роби` (їх отримує модель).

**4.4.** У моделі немає пам'яті між викликами. Ефект пам'яті створює Claude Code: на кожному кроці
він надсилає моделі всю розмову від початку — системний промпт, контекст проєкту, усі попередні

**4.5.** Так: разом із новим питанням надсилається вся розмова, включно з трьома файлами. Звідси:
непов'язане питання краще ставити в новій розмові — так модель не читає зайвого, і це дешевше

**4.6.** Зразок:
```
промпт → контекст
```

Точний набір кроків у Claude може бути іншим; важливо, що є всі три фази і що кожен результат

**4.12.** Зразок. Промпти: «Покажи, яку команду чи який пошук ти виконав і по яких файлах»;
«Наведи кількість рядків із рівнями ERROR і FATAL за сьогоднішню дату — і саму команду». Куди

**4.13.** На кожному кроці модель отримує всю історію. У довгій розмові з десятком файлів кожне
нове коротке питання тягне за собою всі ці файли — модель щоразу читає величезний текст. У коротких
розмовах кожна несе лише своє. Лишатися в одній розмові варто, коли задача одна й та сама і
