# Урок 15. Агенти й субагенти

*Claude Code уміє не лише працювати сам, а й відправляти помічника: окремого агента, який виконає
частину роботи у своєму контексті й поверне короткий звіт. Це зручно для пошуку по багатьох файлах,
для довгих логів і для свіжого погляду на чужу роботу — але кожен помічник витрачає токени. Після
уроку ти розумієш, що таке субагент і що він отримує на старті, розпізнаєш його роботу в
інтерфейсі, створюєш власного субагента-рецензента тест-кейсів і знаєш, коли субагент виправданий,
а коли тільки дорожчий.*

## Коротко

*Картка уроку: прочитай її перед уроком і повернись до неї після.*

**Одним реченням.** Субагент — другий агент, якого головний Claude запускає для окремої задачі: він
працює у власному контекстному вікні й повертає тільки підсумок.

**Навіщо.** Щоб довгий вивід (пошук, логи, тести) не засмічував розмову, щоб паралельно робити
незалежні частини і щоб отримати рецензента, який не бачив, як писалась робота.

**Де.** Рядок на кшталт `test-case-reviewer(Review login tests)` у розмові; `/tasks` — фонові
задачі; свої субагенти — файли в `.claude/agents/` (проєкт) або `~/.claude/agents/` (усі проєкти).

**Модель**

- **Агент** — модель, що працює в циклі з інструментами й метою (урок 8); сам Claude Code — агент.
- **Субагент** — агент-помічник, якого запускає головний Claude через інструмент `Agent`.
- **Вбудовані субагенти** — `Explore` (швидкий пошук, лише читання), `Plan` (дослідження для
  плану), `general-purpose` (будь-яка багатокрокова задача).
- **Власний субагент** — Markdown-файл з `name`, `description` і системним промптом.
- **Фоновий субагент** — працює паралельно з тобою; результат приходить пізніше окремим повідомленням.

**Запам'ятай**

1. Субагент **не бачить твоєї розмови** й твоєї auto memory; отримує свій системний промпт,
   опис задачі, `CLAUDE.md` (крім `Explore` і `Plan`) і знімок git status.
2. Звіт субагента настільки добрий, наскільки точне завдання: давай конкретику.
3. Кожен субагент витрачає власні токени з того самого ліміту, що й головна розмова.
4. Субагент не робить відповідь «розумнішою»: він дає паралельність, чистий контекст або свіжий погляд.
5. `@agent-<name>` гарантує запуск саме цього субагента; у `description` — коли його кликати.

**Пастки** (симптом → причина)

- Субагент «не знає», про що ви домовились у чаті → він не бачить розмови; повтори важливе в завданні.
- Новий субагент не знаходиться → папка `agents` з'явилась після старту сесії; перезапусти Claude Code.
- Ліміт використання тане швидше, ніж зазвичай → кілька субагентів працювали паралельно.

**Як перевірити**

- У `.claude/agents/` твоєї папки-практики лежить `test-case-reviewer.md`; виклик
  `@agent-test-case-reviewer` показує рядок з його іменем, а звіт містить конкретні зауваження
  до тест-кейсів і жодних змін у файлах.

## 15.1. Агент і субагент

З уроку 8 ти знаєш: **агент** — це модель, яка працює в циклі з інструментами й метою: зібрати
інформацію → діяти → перевірити → знову. Claude Code — саме такий агент.

**Субагент** — другий, допоміжний агент, якого головний Claude запускає для частини роботи. Він
отримує власне свіже контекстне вікно, виконує задачу і повертає головному Claude **тільки
короткий звіт**. Документація: "Subagents are specialized AI assistants that handle specific types
of tasks."

Згадай аналогію зі «столом» з уроку 6: контекст — це стіл, на якому лежить усе, з чим працює
Claude. Якщо головний Claude сам перегляне 60 файлів, щоб знайти одну функцію, усі 60 опиняться на
його столі. Субагент переглядає їх на **своєму** столі, а повертає одне речення: «Потрібна функція —
`calculateTax()` у `billing/tax.ts`, рядок 88». Стіл головного Claude лишається чистим.

Ще одна аналогія: ти керівник тестування й просиш колегу: «Пробіжись по архіву логів за тиждень і
скажи, коли вперше з'явилась помилка 502». Колега годину гортає логи, а тобі приносить одну
відповідь. Тобі не треба знати, які файли він відкривав, — тобі потрібен висновок.

⏸ **Зупинись і перевір себе.** Що саме повертається в головну розмову, коли субагент закінчив?

> **Відповідь.** Тільки його підсумковий звіт. Усе, що він прочитав і запускав по дорозі, лишається
> в його власному контексті й до головної розмови не потрапляє.

## 15.2. Що субагент отримує на старті, а чого — ні

Тут легко помилитися, тож запам'ятай точно. Субагент **не** починає «з абсолютно порожнього
аркуша» — він починає **без твоєї розмови**.

| субагент отримує | субагент не отримує |
|---|---|
| власний системний промпт (інструкції саме цього агента) і базові дані про середовище, наприклад робочу папку | історію твоєї розмови з головним Claude |
| повідомлення-завдання, яке пише для нього головний Claude | файли, які головний Claude уже прочитав |
| `CLAUDE.md` усіх рівнів, правила з `.claude/rules/`, `CLAUDE.local.md` (урок 14) — **крім** `Explore` і `Plan` | auto memory головної розмови (урок 14) |
| знімок стану git-репозиторію — **крім** `Explore` і `Plan` | твій стиль відповідей (output style) |
| скіли, прописані в його налаштуваннях (урок 16) | скіли, які ти вже викликав у розмові |

Документація про пам'ять: "The main conversation's auto memory isn't loaded into subagents".
Тобто те, що Claude пам'ятає про тебе, субагент не знає.

`Explore` і `Plan` навмисно стартують без `CLAUDE.md` і без стану git — так дослідження швидше й
дешевше. Якщо правило мусить дійти до субагента (наприклад, «не заглядай у папку `archive/`»),
документація радить просто повторити його в завданні.

Є виняток, про який варто знати: **форк** (fork) — субагент, який отримує всю поточну розмову
замість чистого старту. Claude Code може запускати форки сам; детальніше — в документації, для
початку достатньо звичайних субагентів.

### Звідси головне правило

Звіт субагента настільки добрий, наскільки точне завдання. Головний Claude пише це завдання за
тебе, але якщо твоє прохання розмите, розмитим буде й завдання. Порівняй:

| розмито | конкретно |
|---|---|
| «Подивись тест-кейси через субагента» | «Через субагента перевір усі файли `*-tests.md`: у кожного тест-кейсу мають бути ID, передумови й очікуваний результат. Поверни список файлів і ID, де чогось бракує» |

⏸ **Зупинись і перевір себе.** Ти пів години пояснював Claude, що в проєкті статус «Blocked» означає
«неможливо виконати через середовище». Потім він запускає субагента, щоб розставити статуси в
тест-звіті. Чи знає субагент твоє визначення?

> **Відповідь.** Тільки якщо головний Claude переказав його в завданні або воно записане в
> `CLAUDE.md`. Розмову субагент не бачить. Надійніше записати визначення в `CLAUDE.md` (урок 14) —
> тоді його отримає і головний Claude в кожній сесії, і більшість субагентів.

## 15.3. Вбудовані субагенти

Claude Code має кілька готових субагентів і сам вирішує, коли їх запускати:

| субагент | що робить | особливості |
|---|---|---|
| **Explore** | швидкий пошук і аналіз файлів | тільки читання: Write і Edit заборонені; без `CLAUDE.md` і стану git |
| **Plan** | дослідження проєкту для плану в режимі планування (урок 9) | тільки читання; без `CLAUDE.md` і стану git |
| **general-purpose** | складні багатокрокові задачі, де треба і шукати, і змінювати | усі інструменти, доступні субагентам |

Коли Claude запускає `Explore`, він обирає ретельність: **quick** — точковий пошук, **medium** —
збалансований, **very thorough** — всеохопний аналіз.

Є ще кілька службових, які зазвичай запускаються самі: `claude` (універсальний, коли задача не
підходить під спеціалізованого), `statusline-setup` (налаштування рядка стану через `/statusline`),
`claude-code-guide` (відповідає на питання про можливості Claude Code).

Важлива відмінність: `Explore` і `Plan` — **одноразові**. Звичайного субагента можна потім
«продовжити» (розділ 15.6), а ці — ні.

## 15.4. Як виглядає робота субагента

### Хто вирішує

Зазвичай — сам Claude. Субагента запускає інструмент `Agent` (урок 8); дозволу на сам запуск він
не потребує. Ти бачиш у розмові рядок з іменем субагента і коротким описом задачі, наприклад
`code-improver(Suggest code improvements)`.

### Фон

Субагент, якого Claude запускає з головної розмови, за замовчуванням працює **у фоні**: ти можеш
писати далі, а його результат прийде окремим повідомленням пізніше. Якщо спитати Claude про прогрес
раніше, він скаже, що субагент ще працює.

- `/tasks` показує фонову роботу поточної сесії, зокрема субагентів, і модель, на якій кожен працює.
- Якщо фоновому субагенту потрібен дозвіл (урок 9), запит з'являється в головній сесії з іменем
  субагента. Погодь — і він працює далі; `Esc` — відмова саме для цього виклику, сам субагент не
  зупиняється.
- Сам субагент із тобою не розмовляє: він звітує головному Claude, а той — тобі.

### Як попросити словами

Тобі не потрібен спеціальний синтаксис — достатньо попросити. *Приклади промптів:*

```
Use a subagent to find every place we send emails, and give me a list with file and line.
```

```
Через субагента прочитай logs/app.log і поверни тільки рядки з ERROR, згруповані за типом помилки.
```

```
Коли закінчиш, запусти субагента, щоб він свіжим поглядом перевірив твої зміни на помилки.
```

Останній приклад — це ідея «рецензента, який не бачив, як писався код». Той самий принцип у
вбудованій команді `/code-review` (урок 13): вона переглядає зміни у свіжому субагенті, що не бачив
твоєї розмови.

⏸ **Зупинись і перевір себе.** Ти попросив субагента прочитати великий лог і пишеш Claude наступне
питання. Чи мусиш чекати, поки субагент закінчить?

> **Відповідь.** Ні. За замовчуванням субагент працює у фоні, тож можна продовжувати розмову. Його
> результат прийде пізніше окремим повідомленням; стан можна глянути в `/tasks`.

## 15.5. Власні субагенти

Якщо ти раз у раз просиш «того самого помічника з тими самими інструкціями», його варто зберегти
як файл. Власний субагент — це Markdown-файл: угорі блок налаштувань між `---` (frontmatter, урок
14), нижче — його **системний промпт**, тобто постійна інструкція, з якою він стартує.

*Приклад рецензента тест-кейсів:*

```
---
name: test-case-reviewer
description: Reviews test case files for missing fields and vague steps. Use after test cases are written or changed.
tools: Read, Grep, Glob
model: haiku
---

You review manual test cases. For each test case check: an ID, preconditions,
numbered steps with one action each, and a concrete expected result.
Report only real gaps as a list: file, test case ID, what is missing.
Do not rewrite the test cases. Answer in Ukrainian.
```

| поле | обов'язкове | що означає |
|---|---|---|
| `name` | так | унікальне ім'я, наприклад `test-case-reviewer`; без двокрапки; за ним субагента кличуть |
| `description` | так | **коли** Claude має делегувати цьому субагенту; Claude читає це, щоб вирішити |
| `tools` | ні | дозволені інструменти; без поля — усі, доступні субагентам |
| `model` | ні | модель: `haiku`, `sonnet`, `opus`, `fable` або `inherit`; без поля — зазвичай модель головної розмови |

Два корисні прийоми з документації:

- **Тільки читання.** `tools: Read, Grep, Glob` — і рецензент фізично не може редагувати файли.
  Це обмеження виконує Claude Code, а не «прохання в промпті».
- **Дешевша модель.** `model: haiku` для простої роботи (зібрати файли, перевірити поля). Така
  задача не потребує великої моделі, а Haiku коштує значно менше за запит.

Щоб Claude охочіше кликав субагента сам, документація радить додати в поле `description` фразу на
кшталт "use proactively". Опис тримай коротким: описи всіх субагентів займають
контекст головної розмови.

### Де лежать файли

| місце | для кого | пріоритет при однакових іменах |
|---|---|---|
| `.claude/agents/` у проєкті | цей проєкт; можна закомітити для команди | вищий |
| `~/.claude/agents/` | усі твої проєкти на цьому комп'ютері | нижчий |

(Ще є субагенти організації, субагенти з плагінів (урок 17) і з прапорця `--agents` під час
запуску; для початку тобі потрібні два рядки з таблиці.)

### Як створити

- **Попросити Claude.** Найпростіше: «Створи субагента test-case-reviewer у .claude/agents/, який
  перевіряє тест-кейси на відсутні поля, тільки читає файли і працює на Haiku». Claude напише файл
  з `name`, `description`, `tools`, `model` і системним промптом. Відкрий файл і перевір.
- **Вручну** — створити файл у потрібній папці.
- Команда `/agents` у сучасних версіях лише нагадує: попроси Claude або редагуй папки
  `.claude/agents/` і `~/.claude/agents/` напряму.

Claude Code стежить за цими папками й підхоплює зміни за кілька секунд. Виняток: якщо папки
`agents` ще не було, коли сесія стартувала, — перезапусти Claude Code (`exit`, потім `claude`).

⏸ **Зупинись і перевір себе.** У тебе є `~/.claude/agents/reviewer.md` і в проєкті
`.claude/agents/reviewer.md`, обидва з `name: reviewer`. Який спрацює в цьому проєкті?

> **Відповідь.** Проєктний: `.claude/agents/` має вищий пріоритет за `~/.claude/agents/`. (Зверни
> увагу: у скілів, урок 16, навпаки — особистий переважає проєктний.)

## 15.6. Як викликати субагента явно і як продовжити його роботу

Три способи, від м'якого до жорсткого:

| спосіб | як | що гарантує |
|---|---|---|
| словами | «Use the test-case-reviewer subagent on login-tests.md» | нічого: Claude вирішує, чи делегувати |
| @-згадка | набери `@` і обери субагента зі списку підказок, або напиши вручну `@agent-test-case-reviewer` | запуститься саме цей субагент для цієї задачі |
| уся сесія | `claude --agent test-case-reviewer` | уся сесія працює як цей субагент, з його інструментами й моделлю |

При @-згадці весь твій текст однаково йде головному Claude, і завдання для субагента пише він. Ти
керуєш тим, **кого** запустять, а не точним текстом завдання. Коли пишеш `@agent-…` вручну, список
підказок показує файли, а не агентів, — це нормально, згадка однаково спрацює.

### Продовжити, а не почати заново

Кожен виклик створює нового субагента. Щоб продовжити роботу попереднього з усією його історією,
просто попроси Claude продовжити:

```
Use the test-case-reviewer subagent to review login-tests.md
[субагент закінчив]

Продовж ту перевірку і тепер подивись ще на signup-tests.md
```

Claude відновить того самого субагента, і той пам'ятає, що вже перевіряв. Не вийде з `Explore` і
`Plan` — вони одноразові. Якщо продовження потрібне, проси `general-purpose` або власного субагента.

## 15.7. Скільки це коштує і коли субагент не потрібен

### Вартість

Документація прямо: "Each subagent runs in its own context window with a custom system prompt,
specific tool access, and independent permissions. It also sends its own requests, which count
toward the same usage limits as your main conversation." Тобто кожен субагент шле **власні**
запити до моделі, і вони рахуються в той самий ліміт плану (урок 5).

- Кілька субагентів паралельно витрачають ліміт швидше.
- Звіти субагентів повертаються в головну розмову: двадцять детальних звітів самі заповнять
  контекст. Проси короткі підсумки.
- Свіжому субагенту спершу треба зібрати контекст, який твоя розмова вже мала, тож він може
  виявитися **повільнішим**, ніж зробити задачу на місці.
- `/usage` на планах Pro, Max, Team і Enterprise показує, яку частку використання забирає кожен
  тип субагента.

### Чого субагент не дає

Документація перелічує поради, від яких тепер варто відмовитись:

| стара порада | як тепер |
|---|---|
| «Використовуй субагентів, щоб захистити контекстне вікно» | вікна великі, закінчення контексту — рідкість; субагенти добрі для паралельної роботи, прибирання шумного виводу й незалежного рев'ю, але кожен коштує додаткових токенів |
| «Делегуй субагенту, щоб отримати кращу відповідь» | та сама задача в субагента не стає кращою; допомагає свіжий рецензент, бо він не бачив твоїх міркувань, — а це інше |

### Коли субагент виправданий

| головна розмова | субагент |
|---|---|
| задача потребує частих уточнень | задача дає багато виводу, який тобі не потрібен (логи, повний прогін тестів, широкий пошук) |
| етапи ділять багато спільного контексту (план → зміни → перевірка) | треба обмежити інструменти (рецензент, що тільки читає) |
| маленька точкова зміна | робота самодостатня й може повернути підсумок |
| важлива швидкість | потрібен погляд того, хто не бачив, як робилась робота |

Якщо в тебе просто питання про те, що вже є в розмові, — субагент не потрібен: команда `/btw`
для побічного питання бачить усю розмову, не має інструментів, а відповідь не додається в історію.

### Просунуте — лише знати, що існує

Для дуже великих задач є **dynamic workflows** — "a JavaScript script that orchestrates many
subagents at once", а також фонові сесії (`claude --bg`, перелік — `claude agents`). Це просунуті й
дорогі інструменти; на старті достатньо звичайних субагентів.

Джерело: [Create custom subagents](https://code.claude.com/docs/en/sub-agents),
[Best practices](https://code.claude.com/docs/en/best-practices).

⏸ **Зупинись і перевір себе.** Колега пропонує: «Давай кожне питання до Claude віддавати
субагенту — так контекст буде чистий і відповіді точніші». Що з цього правда?

> **Відповідь.** Майже нічого. Субагент не дає точнішої відповіді на ту саму задачу, а кожен коштує
> додаткових токенів і часу на збирання контексту. Контекст сьогодні рідко закінчується. Субагент
> виправданий для шумного виводу, паралельних незалежних задач, обмеження інструментів і свіжого
> рев'ю — не «для всього».

## 15.9. У роботі QA

- **Пошук по логах.** «Через субагента пройди `logs/` за вчора й поверни тільки перший час появи
  помилки 502 і три рядки контексту навколо» — сотні рядків логів не заходять у твою розмову.
- **Рецензент тест-кейсів.** Власний `test-case-reviewer` з `tools: Read, Grep, Glob` перевіряє
  повноту полів і не може «випадково виправити» файли.
- **Свіжий погляд на баг-репорт.** Після того як ти з Claude написав баг-репорт, попроси субагента
  перевірити, чи зрозумілі кроки людині, яка не бачила вашої розмови, — саме в такому стані його
  прочитає розробник.
- **Повний прогін тестів.** «Через субагента запусти тести й поверни тільки ті, що впали, з
  повідомленням про помилку» — довгий вивід лишається в субагента.
- **Порівняння специфікації з тест-покриттям.** Окремий субагент читає вимоги й тест-кейси та
  повертає список вимог без жодного тест-кейсу.

## 15.10. Типові помилки

### Симптом → причина

| симптом | причина | що зробити |
|---|---|---|
| субагент ігнорує домовленість із чату | він не бачить твоєї розмови | повтори в завданні або запиши в `CLAUDE.md` |
| субагент не знає того, що Claude «пам'ятає» про тебе | auto memory в субагентів не завантажується | потрібне — в завдання або `CLAUDE.md` |
| `Explore` не дотримався правила з `CLAUDE.md` | `Explore` і `Plan` стартують без `CLAUDE.md` | повтори правило в промпті |
| новий субагент «не існує» | папка `agents` з'явилась після старту сесії | перезапусти Claude Code |
| Claude не кличе твого субагента сам | `description` не каже, коли його кликати | допиши «Use after …» або «use proactively»; або `@agent-<name>` |
| рецензент сам «полагодив» файли | у нього немає обмеження `tools` | `tools: Read, Grep, Glob` |
| ліміт використання тане швидко | багато субагентів паралельно, кожен зі своїми запитами | менше субагентів, `model: haiku` для простих, короткі звіти, `/usage` |
| «продовж ту перевірку» почало все з нуля | це був `Explore` або `Plan` — вони одноразові | для продовжуваної роботи — `general-purpose` або власний субагент |
| звіт субагента розмитий | розмите завдання | конкретика: які файли, що шукати, який формат звіту |
| чекаєш відповіді, а вона «пропала» | субагент працює у фоні | продовжуй роботу; дивись `/tasks`; результат прийде окремо |

## 15.11. Що варто запам'ятати

1. Субагент — агент-помічник у власному контексті; у головну розмову повертається тільки звіт.
2. Він отримує свій системний промпт, завдання, `CLAUDE.md` і стан git (крім `Explore` і `Plan`);
   не отримує твоєї розмови й auto memory.
3. Вбудовані: `Explore` і `Plan` — лише читання й одноразові; `general-purpose` — усе.
4. За замовчуванням субагент працює у фоні; `/tasks` показує його стан і модель.
5. Власний субагент: файл з `name`, `description`, за бажанням `tools` і `model`; проєктний
   `.claude/agents/` переважає особистий `~/.claude/agents/`.
6. `@agent-<name>` гарантує запуск; «use proactively» в `description` заохочує Claude кликати сам.
7. Кожен субагент витрачає токени з того самого ліміту; не роби відповідь «кращою» делегуванням.
8. Виправдано: шумний вивід, паралельні незалежні задачі, обмеження інструментів, свіже рев'ю.

# Розв'язки

**15.1.** Агент — модель, яка в циклі збирає інформацію, діє інструментами й перевіряє результат,
поки не досягне мети; Claude Code — агент. Субагент — такий самий агент, але запущений головним
Claude для однієї частини роботи: у власному контексті, з власним завданням, і повертає лише звіт.
Аналогія: ти ведеш регресію, а колегу просиш перевірити лише сумісність із Safari й принести
список проблем — ти не стежиш за кожним його кліком, отримуєш тільки підсумок.

**15.2.**

| | власний субагент | `Explore` |
|---|---|---|
| історія розмови | ні | ні |
| `CLAUDE.md` | так | ні |
| auto memory | ні | ні |
| стан git | так | ні |
| завдання від головного Claude | так | так |
| власний системний промпт | так (тіло файлу) | так (вбудований) |

**15.3.** Зразок: «Через субагента прочитай усі файли в `logs/` за 29.10. Поверни тільки рядки з
`ERROR` і `FATAL`, згруповані за текстом помилки, з кількістю й часом першої появи кожної. Не більше
20 рядків звіту». Тут є що читати, що шукати, як групувати і який розмір звіту.

**15.4.** Найчастіше в розмові з'явиться рядок запуску субагента `Explore` з коротким описом
задачі, а потім — короткий перелік файлів (наприклад, `login-tests.md`). Claude може вирішити
відповісти й сам, без делегування: прохання словами не гарантує запуску. Файли не змінились:
`Explore` тільки читає.

**15.5.** У `qa-notes/.claude/agents/` має лежати `test-case-reviewer.md`. Перевір: `ls -Force
.claude/agents` (Windows) або `ls -a .claude/agents` (macOS/Linux). Відкрий файл: перший рядок
`---`, далі `name`, `description`, `tools`, `model`, знову `---` і текст інструкції. Після цього
перезапусти Claude Code, бо папки `agents` на старті сесії не було.

**15.6.** У розмові — рядок з `test-case-reviewer` і описом задачі. У `/tasks` — рядок субагента
з моделлю (якщо в файлі `model: haiku` — модель Haiku). Звіт — список «файл — ID — чого бракує»;
кількість зауважень залежить від того, що Claude написав у `login-tests.md`. Якщо зауважень нуль,
звіт має про це сказати; це теж результат.

**15.7.** Продовжений субагент посилається на вже перевірене («у login-tests.md я раніше
знайшов…») або не перевіряє той файл удруге, а звіт стосується нового файлу в контексті попередніх
висновків. Новий субагент нічого не знав би про першу перевірку. Можна просто спитати Claude, чи
він відновив того самого субагента.

**15.8.** Субагент не зможе змінити файл: у нього є лише `Read`, `Grep`, `Glob`, без `Edit` і
`Write`. Він, найімовірніше, поверне звіт із проблемами або скаже, що змінювати не може. Головний
Claude після цього може виправити файл сам, бо в нього інструменти редагування є. Обмеження діє
тільки на субагента.

**15.9.** 1 — головна розмова: маленька точкова зміна. 2 — субагент: багато виводу, потрібен лише
підсумок. 3 — головна розмова: багато уточнень і спільного контексту. 4 — субагент: свіжий погляд
без вашої розмови. 5 — головна розмова або `/btw`: питання про те, що вже є в розмові, субагент
його не бачить.

**15.10.** Правда: незалежні частини справді можна робити паралельно, і це швидше. Неправда:
відповідь від цього не стає розумнішою — та сама модель на тій самій задачі. Ціна: кожен субагент
шле власні запити з того самого ліміту, три паралельні витрачають ліміт приблизно втричі швидше, а
їхні звіти ще й заповнюють головний контекст. Паралелити варто лише справді незалежні задачі.

**15.11.** Зразок:
```
---
name: log-summarizer
description: Summarizes application log files into error groups. Use proactively whenever the user asks about errors in logs or attaches a log file.
tools: Read, Grep, Glob
model: haiku
---

You summarize log files. Group ERROR and FATAL lines by message text.
For each group give: count, first and last timestamp, one example line.
Return at most 15 lines. Do not suggest fixes. Answer in Ukrainian.
```
`name` — як кликати (`@agent-log-summarizer`). `description` — коли делегувати; «use proactively» і
конкретний тригер (питання про помилки в логах) заохочують Claude кликати самостійно. `tools` —
тільки читання, змінити нічого не зможе. `model: haiku` — групування рядків не потребує великої
моделі, а коштує менше. Тіло — системний промпт: що робити й у якому форматі звітувати.

**15.12.** У цьому проєкті спрацює проєктний `reviewer` з `.claude/agents/`: він має вищий
пріоритет. В іншому проєкті без власного `reviewer` — особистий з `~/.claude/agents/`. Щоб обидва
були доступні скрізь, дай їм різні імена, наприклад `code-reviewer` і `test-case-reviewer`, і
поклади обидва в `~/.claude/agents/` (або проєктний закоміть у кожен потрібний проєкт).
