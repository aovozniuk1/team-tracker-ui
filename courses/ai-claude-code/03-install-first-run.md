# Урок 3. Встановлення і перший запуск

*У цьому уроці Claude Code з'являється на твоєму комп'ютері. Ти дізнаєшся, який акаунт для нього
потрібен, де його можна запускати, як встановити його однією командою і не потрапити в пастки
PowerShell та CMD, як перевірити встановлення і що відбувається під час першого запуску. Після уроку
ти запускаєш Claude Code у власній навчальній папці, входиш в акаунт, відповідаєш на запитання про
довіру до папки, надсилаєш перший промпт і правильно виходиш.*

## Коротко

*Картка уроку: прочитай її перед уроком і повернись до неї після.*

**Одним реченням.** Встановлюєш Claude Code офіційною командою для своєї системи, перевіряєш
`claude --version`, переходиш у папку проєкту, запускаєш `claude` і входиш в акаунт із платним
планом.

**Навіщо.** Без правильного встановлення й входу не запрацює жоден наступний урок; а більшість
проблем новачків — не в Claude Code, а в тому, що команду вставили не в ту оболонку.

**Де.** Термінал (урок 2): PowerShell на Windows, Terminal на macOS і Linux. Без терміналу —
застосунок Claude для комп'ютера, вкладка **Code**.

**Модель**

- **План (підписка)** — Pro, Max, Team чи Enterprise; безкоштовний план Claude Code не включає.
- **Нативне встановлення** — рекомендований спосіб: одна команда, далі програма оновлюється сама.
- **PowerShell і CMD** — дві різні оболонки Windows; команди встановлення для них різні.
- **PATH** — список папок, де система шукає програми, коли ти набираєш їхню назву.
- **Довіра до папки (workspace trust)** — запитання при першому запуску в новій папці: чи довіряєш
  ти її вмісту.

**Запам'ятай**

1. Потрібен платний план або акаунт Claude Console; безкоштовний план не підходить.
2. Після встановлення відкрий **новий** термінал і перевір `claude --version`.
3. У PowerShell запрошення починається з `PS`; команда з `irm` — для PowerShell, з `curl ... &&` —
   для CMD.
4. Перед `claude` переходь у папку проєкту, а не запускай у домашній.
5. Вихід: `exit`, або двічі `Ctrl+C` на порожньому рядку.

**Пастки** (симптом → причина)

- `'irm' is not recognized` → ти в CMD, а не в PowerShell.
- `The token '&&' is not a valid statement separator` → вставив команду для CMD у PowerShell.
- `command not found` / `claude is not recognized` одразу після встановлення → не відкрив новий
  термінал або папки програми немає в PATH.

**Як перевірити**

- `claude --version` друкує номер версії, наприклад `2.1.314 (Claude Code)`; у папці
  `ai-course/first-run` Claude Code запускається, приймає промпт і закривається командою `exit`.

## 3.1. Що потрібно: акаунт і план

Claude Code — не безкоштовна програма в тому сенсі, що для роботи потрібен акаунт із доступом до
моделей Claude. Підходить одне з такого:

| варіант | що це | для кого |
|---|---|---|
| **Підписка Pro або Max** | особистий платний план Claude | для більшості учнів цього курсу |
| **Підписка Team або Enterprise** | план, який купує компанія для співробітників | якщо твоя компанія вже має такий план |
| **Акаунт Claude Console** | акаунт для розробників з передплаченими кредитами API; платиш за кожен токен | хто хоче платити за фактичне використання |
| **Хмарні провайдери** | Amazon Bedrock, Google Cloud's Agent Platform (раніше Vertex AI), Microsoft Foundry | компанії, що вже працюють у цих хмарах |

**Безкоштовний план Claude не включає Claude Code.** Звичайним чатом на claude.ai можна
користуватися безкоштовно, а Claude Code — ні.

Різниця між підпискою і Console, коротко (докладно — урок 5):

- **Підписка** не рахує гроші за кожен токен. Натомість твоє використання витрачає **ліміти плану**:
  є вікно на 5 годин, яке постійно «зсувається», і тижневе вікно. Ліміти спільні для всіх моделей і
  для звичайного чату Claude.
- **Console (API)** — платиш за кожен мільйон токенів за прайсом.

Ще одна умова: Claude Code має бути доступний у твоїй країні. Якщо ні, побачиш повідомлення
`App unavailable in region`.

⏸ **Зупинись і перевір себе.** Твій друг зареєструвався на claude.ai і користується безкоштовним
планом. Чи зможе він пройти цей курс без жодних витрат?

> **Відповідь.** Ні. Безкоштовний план Claude Code не включає. Йому потрібна підписка (Pro, Max,
> Team, Enterprise) або акаунт Claude Console з кредитами.

git-scm.com). Це не обов'язково, але рекомендовано: з ним Claude Code отримує інструмент Bash для
запуску команд, а без нього запускає команди через PowerShell. Що таке git — урок 10.

## 3.3. Де можна запускати Claude Code

Claude Code — одна й та сама програма з тими самими ідеями в кількох «оболонках». Усе, що ти вчиш у
цьому курсі, працює всюди; відрізняються лише кнопки.

| де | як виглядає | для чого найкраще |
|---|---|---|
| **Термінал (CLI)** | набираєш `claude` у вікні командного рядка | основний спосіб у цьому курсі; скрипти через `claude -p` |
| **Застосунок для комп'ютера** | вікно зі списком сесій збоку, наочними змінами у файлах, вбудованим терміналом і редактором | новачкам; зручно переглядати зміни; кілька сесій поруч |
| **Веб (claude.ai/code)** | працює в хмарі Anthropic, на ізольованій машині з копією твого репозиторію з GitHub | робота з будь-якого комп'ютера; довгі задачі, що не зупиняються, коли закриваєш ноутбук |
| **Розширення для VS Code і JetBrains** | панель усередині редактора коду | коли пишеш код і хочеш Claude поруч |
| **Інтеграції** | Slack, GitHub Actions, GitLab CI/CD, Claude in Chrome | питати Claude з командного чату; автоматична робота; задачі в браузері |

Веб-версія потребує плану Pro, Max, Team або Enterprise і репозиторію на GitHub — це пізніший етап.
Застосунок для комп'ютера потребує **платної підписки**.

**CLI** (від англ. *command-line interface*) — «інтерфейс командного рядка», тобто програма, якою
керують із терміналу. Коли в курсі написано «CLI», мова саме про `claude` у терміналі.

У цьому курсі ми працюємо переважно в терміналі: так видно кожну команду, і все, що ти вивчиш, легко
перенести в будь-яку іншу оболонку. Але якщо термінал зовсім не твоє — розділ 3.10 описує шлях без
нього.

⏸ **Зупинись і перевір себе.** Тобі треба, щоб Claude довго працював над задачею, поки твій ноутбук
закритий. Яка з оболонок для цього підходить?

> **Відповідь.** Веб (claude.ai/code): він працює в хмарі Anthropic, тож задача триває, навіть коли
> ноутбук закрито. Для цього потрібен репозиторій на GitHub.

## 3.4. Встановлення в терміналі

### Крок 0. Дізнайся, в якій ти оболонці

На Windows є дві оболонки, і їх легко сплутати:

| оболонка | як упізнати запрошення |
|---|---|
| **PowerShell** | рядок починається з `PS`, наприклад `PS ...\Users\Olena>` |
| **CMD** (старий командний рядок) | без `PS`, наприклад `...\Users\Olena>` |

У Windows Terminal нова вкладка зазвичай відкривається з PowerShell. У цьому курсі ми працюємо в
PowerShell.

### Крок 1. Встав офіційну команду

Відкрий термінал і встав **одну** команду — ту, що для твоєї системи:

**macOS, Linux, WSL:**
```
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows, PowerShell:**
```
irm https://claude.ai/install.ps1 | iex
```

**Windows, CMD:**
```
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

Що тут відбувається, на пальцях: перша частина завантажує з офіційного сайту скрипт встановлення,
а друга його виконує. Саме тому такі команди треба брати **лише з офіційної документації** —
команда, скопійована з випадкового сайту, так само виконала б чужий скрипт.

Як вставити текст у термінал:

| система | вставити |
|---|---|
| Windows | `Ctrl+V` або правий клік мишкою |
| macOS | `Cmd+V` |
| Linux | `Ctrl+Shift+V` |

### Крок 2. Дочекайся кінця

Інсталятор **не показує індикатора прогресу**. Якийсь час може здаватися, що нічого не
відбувається, — це нормально. Чекай, доки з'явиться нове запрошення. Не натискай `Ctrl+C`: це
перерве встановлення (урок 2).

### Крок 3. Відкрий НОВИЙ термінал і перевір

Закрий вікно терміналу і відкрий нове. Набери:

```
> claude --version
```

Маєш побачити номер версії, наприклад `2.1.314 (Claude Code)`. Твій номер буде іншим — програма
часто оновлюється, і це нормально.

Чому саме **новий** термінал: вікно, яке було відкрите до встановлення, ще «не знає», де лежить
нова програма. Новий термінал перечитує налаштування й знаходить `claude`.

### Інші способи встановлення

| спосіб | команда | важливо |
|---|---|---|
| Homebrew (macOS) | `brew install --cask claude-code` | не оновлюється автоматично |
| WinGet (Windows) | `winget install Anthropic.ClaudeCode` | не оновлюється автоматично |
| npm | `npm install -g @anthropic-ai/claude-code` | потрібен Node.js 22 або новіший; ніколи не запускай через `sudo` |

Якщо не знаєш, що таке Homebrew, WinGet чи npm, — тобі не сюди: бери нативне встановлення з
кроку 1. Воно рекомендоване й оновлюється само.

⏸ **Зупинись і перевір себе.** Ти встановив Claude Code, у тому самому вікні набрав
`claude --version` і отримав помилку «не знайдено». Що зробити першим?

> **Відповідь.** Закрити термінал, відкрити новий і повторити `claude --version`. Старе вікно не
> бачить щойно встановленої програми.

## 3.5. Пастки встановлення і як їх розпізнати

### PowerShell чи CMD

Найчастіша проблема — команда не для тієї оболонки. Повідомлення про помилку прямо підказує, що
сталося:

| бачиш | що сталося | що зробити |
|---|---|---|
| `'irm' is not recognized ...` | команду для PowerShell вставили в **CMD** | відкрий PowerShell (запрошення з `PS`) або візьми команду для CMD |
| `The token '&&' is not a valid statement separator` | команду для CMD вставили в **PowerShell** | візьми команду з `irm` для PowerShell |

Читай помилку повністю, як учив урок 2: у ній написано і що не так, і де.

### «Команду не знайдено» навіть у новому терміналі

Тут треба розібратися з поняттям **PATH**. Коли ти набираєш `claude`, система не обшукує весь диск.
Вона дивиться в короткий список папок — він і називається PATH (шлях пошуку програм). Якщо папки з
`claude` у списку немає, буде «не знайдено», хоча програма встановлена.

Аналогія: PATH — це список полиць, на яких ти шукаєш ключі. Якщо ключі лежать на полиці, якої немає
у списку, ти їх «не знайдеш», хоча вони вдома.

Нативне встановлення кладе `claude` у твою домашню папку:

| система | папка, яка має бути в PATH |
|---|---|
| macOS, Linux | `~/.local/bin` |
| Windows | `%USERPROFILE%\.local\bin` |

(`%USERPROFILE%` у Windows означає те саме, що `~`: твою домашню папку.)

Як додати папку в PATH:

- **Windows.** Натисни `Win`, набери «змінні середовища» (англ. *environment variables*) і відкрий
  **Edit environment variables for your account** («Змінити змінні середовища для облікового
  запису»). У верхньому списку обери `Path` → **Edit** → **New** → встав `%USERPROFILE%\.local\bin`
  → **OK** у всіх вікнах. Відкрий новий термінал.
- **macOS (оболонка Zsh).** Виконай команду, потім відкрий новий термінал:
  ```
  echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
  ```
- **Linux (оболонка Bash).** Те саме, але у файл `~/.bashrc`:
  ```
  echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
  ```

⏸ **Зупинись і перевір себе.** Ти в PowerShell вставив `curl -fsSL https://claude.ai/install.cmd
-o install.cmd && install.cmd && del install.cmd` і отримав помилку про `&&`. Що не так?

> **Відповідь.** Це команда для CMD, а ти в PowerShell. У PowerShell треба вставити
> `irm https://claude.ai/install.ps1 | iex`.

## 3.6. Перевірка встановлення: чотири команди

Ці команди запускаються в терміналі, **поза** Claude Code, — просто як звичайні команди.

| команда | що робить |
|---|---|
| `claude --version` | друкує номер версії, наприклад `2.1.314 (Claude Code)` (коротко: `claude -v`) |
| `claude --help` | показує всі параметри командного рядка й підкоманди |
| `claude doctor` | перевіряє здоров'я встановлення |
| `claude update` | перевіряє, чи є новіша версія, і встановлює її |

### `claude --help`

Вивід довгий, і це нормально: тобі зараз потрібні лише кілька рядків. Пошукай у ньому `--version`
і `--model` — побачиш короткий опис кожного параметра. Повертайся до `--help` щоразу, коли в курсі
трапиться новий параметр: так ти переконаєшся, що він є саме у твоїй версії.

### `claude doctor`

Опис із `claude --help`: "Check the health of your Claude Code installation". Він перевіряє, чи все
встановлено як слід, і повідомляє про проблеми. Для повнішої перевірки, яка може й виправити
проблеми, у самій сесії Claude Code є команда `/doctor`.

### Оновлення

Нативне встановлення **оновлюється само у фоні**. Якщо хочеш оновитися зараз — `claude update`.
Встановлене через Homebrew чи WinGet саме не оновлюється.

> **Про версії.** Курс звірено з документацією на 30.10.2026. Перевір свою версію
> (`claude --version`) і за потреби онови (`claude update`). Claude Code змінюється дуже швидко:
> якщо щось у тебе виглядає інакше, ніж у курсі, — офіційна документація має рацію.

⏸ **Зупинись і перевір себе.** Як дізнатися, чи підтримує твоя версія параметр, про який ти
прочитав у статті?

> **Відповідь.** Запустити `claude --help` і пошукати цей параметр у виводі. Якщо його там немає —
> онови Claude Code (`claude update`) і перевір ще раз.

## 3.7. Перший запуск у порожній папці

### Крок 1. Підготуй папку

Як вчив урок 2, Claude Code запускають **у папці проєкту**. Для першого знайомства створи порожню
навчальну папку:

```
> cd ~/Documents
> mkdir ai-course
> cd ai-course
> mkdir first-run
> cd first-run
> pwd
```

Якщо папка `ai-course` уже є (з уроку 2) — команда `mkdir ai-course` скаже, що вона існує; просто
переходь далі. Останній рядок має показати шлях, що закінчується на `ai-course\first-run` (Windows)
або `ai-course/first-run` (macOS, Linux).

Чому порожня папка: Claude нічого тут не зламає, а ти спокійно роздивишся інтерфейс.

### Крок 2. Запусти

```
> claude
```

### Крок 3. Увійди в акаунт (лише першого разу)

1. Claude Code відкриває браузер зі сторінкою входу. Якщо браузер не відкрився сам, натисни `c` —
   адреса сторінки скопіюється, і ти вставиш її в браузер вручну.
2. Увійди в свій акаунт Claude і підтверди доступ.
3. Якщо браузер показав код — скопіюй його і встав у термінал, де чекає Claude Code.
4. Побачиш `Login successful` — натисни `Enter`.

Наступного разу входити не треба: Claude Code пам'ятає вхід.

Перемикатися між акаунтами можна всередині Claude Code: `/login` — увійти в інший акаунт, `/logout`
— вийти. Рядок, що починається з `/`, — це **команда** Claude Code, а не звичайне повідомлення для моделі
(докладно — урок 16).

> **Пастка зі змінною `ANTHROPIC_API_KEY`.** Якщо на комп'ютері задано змінну середовища
> `ANTHROPIC_API_KEY` (такий ключ API іноді лишається після інших програм чи курсів) і ти погодився
> її використати, Claude Code працюватиме через цей ключ, а не через підписку, — і використання
> оплачуватиметься за прайсом API. Якщо ти хотів працювати за підпискою, на таке запитання
> відповідай «ні».

Під час першого запуску можуть з'явитися й інші короткі екрани налаштування. Якщо не впевнений,
що обрати, — лишай варіант за замовчуванням: усе це можна змінити пізніше.

### Крок 4. Запитання про довіру до папки

Коли ти **вперше** запускаєш Claude Code у папці, він питає, чи довіряєш ти цій папці (*workspace
trust*). Навіщо: у папці проєкту можуть лежати налаштування Claude Code, які вмикають автоматичні
дії, — наприклад, файли в прихованій папці `.claude` (урок 2) чи список підключених зовнішніх
інструментів. Поки ти не підтвердив довіру, такі налаштування з папки не діють на повну.

Як відповідати:

- **Твоя власна папка** (ти сам її створив, як `first-run`) — підтверджуй довіру.
- **Чужа папка**, скачана з інтернету чи отримана від незнайомця, — спершу подивись, що в ній є.
  Якщо сумніваєшся — не погоджуйся: без довіри Claude Code у цій папці не працюватиме.

Відповідь запам'ятовується для цієї папки, і наступного разу питання не буде. Виняток — **домашня
папка**: якщо запустити Claude Code просто в ній, довіра не зберігається, і питання повторюється
щоразу. Ще одна причина запускати його в папці проєкту.

⏸ **Зупинись і перевір себе.** Чому Claude Code питає про довіру до папки, а не просто відкривається?

> **Відповідь.** Бо в папці проєкту можуть лежати налаштування, які змушують Claude Code щось робити
> автоматично. Поки ти не підтвердив, що довіряєш вмісту, такі налаштування з чужої папки не
> повинні спрацьовувати.

## 3.8. Перший промпт

Після входу і довіри ти бачиш **поле вводу** — місце, де пишеш Claude. Набери повідомлення і
натисни `Enter`.

Почни з короткого, дешевого запиту:

```
Привіт! Скажи одним реченням, у якій папці ми зараз працюємо.
```

Що може статися:

- Claude відповість одразу, назвавши папку `first-run`: шлях до робочої папки він знає від початку.
- Або спершу виконає маленьку команду, щоб перевірити, — побачиш рядок виклику інструмента, і
  лише потім відповідь. Такі рядки й називаються викликами інструментів (уроки 4 і 8).

Обидва варіанти правильні. Головне — Claude назвав саме твою папку.

Кілька речей, які видно на екрані і які ми розберемо пізніше:

- Під полем вводу показано **режим дозволів** — наскільки самостійно Claude діє. У свіжих версіях
  Claude Code за замовчуванням зазвичай увімкнено auto mode: окрема модель перевіряє ризиковані дії замість
  того, щоб питати тебе про кожну. Як перемкнутися в режим, де Claude питає про все, — урок 9.
- Кожен промпт витрачає трохи ліміту твого плану. Короткі запити в порожній папці — дуже дешеві,
  тож не бійся експериментувати; великі задачі — інша розмова (урок 5).

### Що Claude бачить у твоїй папці

Документація описує доступ Claude до файлів так: "Files in your directory and subdirectories, plus
files elsewhere with your permission". Тобто файли в робочій папці та її підпапках, а файли деінде —
лише з твого дозволу. Ще одна причина обирати папку свідомо.

⏸ **Зупинись і перевір себе.** Ти запустив Claude Code в `first-run` і просиш «прочитай мій файл
`cv.pdf` з Завантажень». Що, найімовірніше, буде?

> **Відповідь.** Файл поза робочою папкою, тож Claude спитає дозволу, перш ніж його читати (або
> не знайде його, якщо ти не вказав шлях). Простіше скопіювати потрібний файл у робочу папку.

## 3.9. Як вийти з Claude Code

| спосіб | як |
|---|---|
| команда | набери `exit` і натисни `Enter` |
| `Ctrl+C` двічі | на **порожньому** полі вводу натисни `Ctrl+C` двічі поспіль |
| `Ctrl+D` двічі | так само, двічі поспіль |

Нюанс з `Ctrl+C`: якщо в полі вводу є текст, перше натискання лише **очищає** його. Тому, щоб
вийти, поле має бути порожнім — або натисни `Ctrl+C` ще раз.

Після виходу ти знову бачиш звичайне запрошення терміналу (`PS ...>` чи `%`/`$`). Розмова не
зникає: Claude Code зберігає її, і пізніше її можна продовжити (урок 7).

⏸ **Зупинись і перевір себе.** Ти набрав половину промпту, передумав і натиснув `Ctrl+C`. Програма
не закрилася. Чому?

> **Відповідь.** Перше натискання `Ctrl+C` очистило поле вводу. Щоб вийти, одразу натисни `Ctrl+C`
> ще раз (або набери `exit`).

## 3.10. Шлях без терміналу: застосунок для комп'ютера

Якщо термінал лякає або не працює, є застосунок Claude для комп'ютера — у ньому той самий Claude
Code, але з кнопками. Пам'ятай: для нього потрібна **платна підписка**.

1. Встанови застосунок Claude для комп'ютера з офіційного сайту (claude.ai).
2. Увійди в акаунт.
3. Відкрий вкладку **Code**.
4. Нова сесія — кнопка **+ New** на бічній панелі (або `Ctrl+N` на Windows, `Cmd+N` на macOS).
5. Під полем вводу обери папку проєкту — елемент **Project folder** — і середовище **Environment**:
   `Local` (твій комп'ютер), `Cloud`, `SSH` або `WSL`. Для цього курсу — `Local`.
6. Напиши промпт у полі вводу.

Застосунок зручний ще й тим, що зміни у файлах показує наочно, а сесії видно списком збоку. Усі
ідеї курсу — промпти, контекст, дозволи, відкат — працюють тут так само; відрізняються лише кнопки
замість команд. Там, де в уроці є команда терміналу, у застосунку зазвичай є відповідна кнопка або
та сама команда з `/` у полі вводу.

> [academy.claude.com/courses/claude-code-101](https://academy.claude.com/courses/claude-code-101).

Джерело: [документація Claude Code](https://code.claude.com/docs).

## 3.12. Типові помилки

### Симптом → причина

| симптом | причина | що зробити |
|---|---|---|
| `'irm' is not recognized` | ти в CMD | відкрий PowerShell або візьми команду для CMD |
| `The token '&&' is not a valid statement separator` | команда для CMD у PowerShell | візьми команду з `irm` |
| `claude` «не знайдено» одразу після встановлення | старе вікно терміналу | відкрий новий термінал |
| `claude` «не знайдено» і в новому терміналі | папки `.local/bin` немає в PATH | додай її в PATH (розділ 3.5) |
| здається, що встановлення зависло | інсталятор не показує прогресу | чекай нового запрошення, не тисни `Ctrl+C` |
| вхід проходить, але Claude Code не працює з безкоштовним акаунтом | безкоштовний план не включає Claude Code | потрібна підписка або Console |
| `App unavailable in region` | Claude Code недоступний у твоїй країні | — |
| питання про довіру з'являється при кожному запуску | запускаєш у домашній папці | `cd` у папку проєкту |
| використання оплачується за API, хоча є підписка | погодився використати `ANTHROPIC_API_KEY` | прибери цю змінну середовища або не погоджуйся її використовувати |
| `Ctrl+C` не закриває Claude Code | перше натискання лише очистило поле | натисни `Ctrl+C` ще раз на порожньому полі або набери `exit` |

## 3.13. Що варто запам'ятати

1. Для Claude Code потрібен Pro, Max, Team, Enterprise або акаунт Console; безкоштовний план — ні.
2. Офіційні команди: `curl -fsSL https://claude.ai/install.sh | bash` (macOS, Linux, WSL),
   `irm https://claude.ai/install.ps1 | iex` (PowerShell), окрема команда для CMD.
3. Інсталятор мовчить; після нього — новий термінал і `claude --version`.
4. PowerShell — запрошення з `PS`; помилки про `irm` і `&&` означають «не та оболонка».
5. «Не знайдено» в новому терміналі — додай `~/.local/bin` (`%USERPROFILE%\.local\bin`) у PATH.
6. `claude --help` — усі параметри, `claude doctor` — здоров'я, `claude update` — оновлення.
7. Перший запуск: `cd` у папку проєкту → `claude` → вхід через браузер → довіра до папки.
8. Вихід: `exit` або двічі `Ctrl+C` / `Ctrl+D` на порожньому полі; розмова зберігається.
9. Без терміналу — застосунок для комп'ютера, вкладка **Code**, **+ New**, **Project folder**.

# Розв'язки

**3.1.** Подивись план у налаштуваннях акаунта на claude.ai. Pro, Max, Team чи Enterprise —
підходять. Безкоштовний план — ні: тоді потрібна підписка (наприклад, Pro) або акаунт Claude
Console з передплаченими кредитами API. Компанії можуть давати доступ і через Amazon Bedrock, Google
Cloud's Agent Platform чи Microsoft Foundry.

**3.2.** PowerShell — якщо запрошення починається з `PS` (наприклад `PS ...\Users\Olena>`). Без `PS`
— це CMD. На macOS запрошення зазвичай закінчується на `%` (наприклад `olena@MacBook ~ %`), на Linux
— на `$`.

**3.3.**
1. Помилка `'irm' is not recognized ...`: `irm` — команда PowerShell, CMD її не знає.
2. Помилка `The token '&&' is not a valid statement separator`: так записують команди для CMD.
3. Почнеться встановлення (без індикатора прогресу); у кінці з'явиться нове запрошення. Це правильна
   команда для macOS.

**3.4.** Наприклад, `2.1.314 (Claude Code)` — номер у тебе, найімовірніше, інший, і це нормально.
Якщо `claude` «не знайдено» — перевір, що це новий термінал, і додай папку в PATH (розділ 3.5).

**3.5.** Біля `-v, --version` буде опис на кшталт «Output the version number», біля `--model` —
опис про вибір моделі для поточної сесії (точний текст залежить від версії). У розділі `Commands`
серед підкоманд є `doctor` (перевірка здоров'я встановлення) і `update` (перевірка й встановлення
оновлень). Якщо вивід не вміщується на екран — прокрути вікно вгору.

**3.6.** `claude doctor` покаже результати перевірки встановлення; якщо все гаразд — проблем не
буде. `claude update` або скаже, що в тебе вже остання версія, або завантажить і встановить новішу.
Точні формулювання залежать від версії — важливо, що жодна команда не завершилась помилкою.

**3.7.**
```
> cd ~/Documents
> mkdir ai-course
> cd ai-course
> mkdir first-run
> cd first-run
> pwd
> claude
```
`pwd` має показати шлях, що закінчується на `ai-course\first-run` або `ai-course/first-run`. Довіру
підтверджуємо: папку ти створив сам, і вона порожня, тож нічого чужого в ній немає.

**3.8.** Claude назве папку `first-run` (можливо, з повним шляхом). Рядок виклику інструмента міг
з'явитися, а міг і ні: шлях до робочої папки він знає від запуску, але іноді перевіряє командою.
Обидва варіанти правильні.

**3.9.** Усі три способи повертають тебе до звичайного запрошення терміналу. Коли в полі був текст,
одне натискання `Ctrl+C` лише очистило поле, а програма лишилась відкритою. Щоб вийти, потрібне ще
одне натискання `Ctrl+C` одразу після першого.

**3.10.** «1) Перевір, що нативне встановлення завершилось без помилок (можна запустити команду
встановлення ще раз). 2) Додай `%USERPROFILE%\.local\bin` у PATH: `Win` → "змінні середовища" →
Edit environment variables for your account → `Path` → Edit → New → OK, і відкрий новий термінал.
Потім `claude --version`». На macOS/Linux другий крок — додати `~/.local/bin` у PATH через
`~/.zshrc` або `~/.bashrc`.

**3.11.** Зразок: «PATH — як записник із номерами, за якими ти дзвониш. Набираєш "мама" — і телефон
шукає лише в записнику. Якщо номер є, але не записаний, — "абонента не знайдено". Програма
встановлена, але її папки немає в PATH — система її "не знає"».

**3.12.** Не запускати наосліп. Спершу подивитися вміст, включно з прихованими папками
(`ls -Force` / `ls -a`): у прихованій папці `.claude` можуть бути налаштування, що змушують Claude
Code діяти автоматично. Саме тому Claude Code питає про довіру до нової папки: погодившись, ти
дозволяєш цим налаштуванням діяти. Якщо сумнівно — не погоджуватися на довіру
або взяти з архіву лише потрібні файли в нову власну папку.

**3.13.** Ти маєш побачити ту саму відповідь про папку `first-run`. Типові спостереження: у
застосунку зручно бачити список сесій і зміни у файлах, папку обираєш кнопкою, а не `cd`; у
терміналі ж видно команди й параметри, і все, що ти вивчиш, легко повторити будь-де. Правильної
відповіді тут немає — важливо, що ти пройшов обидва шляхи.

## Ворота уроку

- [ ] назвати, які акаунти підходять для Claude Code, а який — ні;
- [ ] назвати основні системні вимоги, зокрема потребу в інтернеті;
- [ ] перелічити, де можна запускати Claude Code, і для чого кожен варіант;
- [ ] відрізнити PowerShell від CMD за запрошенням;
- [ ] встановити Claude Code офіційною командою для своєї системи;
- [ ] розпізнати помилки `'irm' is not recognized` і `The token '&&'...` і виправити їх;
- [ ] пояснити, що таке PATH і що робити, коли `claude` «не знайдено»;
- [ ] користуватися `claude --version`, `claude --help`, `claude doctor`, `claude update`;
- [ ] запустити Claude Code у папці проєкту й увійти в акаунт;
- [ ] пояснити, навіщо запитання про довіру до папки і як на нього відповідати;
- [ ] пояснити пастку зі змінною `ANTHROPIC_API_KEY`;
- [ ] вийти з Claude Code трьома способами;
- [ ] відкрити нову сесію в застосунку для комп'ютера (якщо є підписка).

Якщо якийсь пункт викликає сумнів — повернись до відповідного розділу.
