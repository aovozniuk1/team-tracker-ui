# Урок 2. Проєкти: список, створення, доступ і налаштування порталу

*Після цього уроку ти розумієш, як влаштований портал Zoho Projects і що живе всередині проєкту,
створюєш проєкт з нуля з правильними полями, бюджетом і доступом, відрізняєш публічний, приватний
і суворий проєкт і знаєш, які налаштування порталу треба ввімкнути до старту. Для QA тут головне:
форма проєкту змінюється від налаштувань порталу, а «відсутнє поле» — ще не дефект.*

---

## 2.1. Портал, проєкт і що в ньому живе

**Портал** — це робочий простір Zoho Projects твоєї організації: його користувачі, налаштування
(**Setup**) і всі проєкти. Адреса твого тріального порталу —
`projects.zoho.eu/portal/<портал>`.

**Проєкт** — контейнер для однієї роботи: впровадження CRM для клієнта, внутрішня розробка,
навчальний проєкт. Усередині проєкту — вкладки. У тріалі стандартні вкладки такі: **Dashboard,
Tasks, Users, Reports, Documents, Phases, Time Logs**; решта ховається під **•••** (More Tabs):
**Issues**, **Feed**, **Timesheet**, а також **Forums** і **Pages**, якщо їх увімкнено. Вкладок
Overview чи Settings у проєкті немає.

Робота в проєкті складається так:

```
Project
  Phase (раніше Milestone)      етап із датами й результатом
    Task List                   група пов'язаних задач
      Task                      одиниця роботи
        Subtask                 частина задачі
  Issues (у списку вкладок — Bugs)   дефекти
  Time Logs                     облік часу
```

Дві заміни назв, які треба знати напам'ять: **Milestones тепер називаються Phases**; модуль
**Issues** у переліку вкладок при створенні проєкту називається **Bugs**.

### Ліве меню порталу

У тріалі ліве меню: **Home, Reports, Projects, Users, Collaboration, My Approvals** і блок
**Overview** з пунктами **Tasks, Issues, Phases, Time Logs, Timesheets** — там задачі, issues,
фази й час з усіх проєктів разом.

### Setup: карта налаштувань порталу

Налаштування відкриваються шестернею у верхньому правому куті; Setup відкривається на сторінці
**Personal Settings**. Ось як виглядає меню Setup у тріалі:

| розділ | пункти |
|---|---|
| PERSONAL PREFERENCES | Personal Settings, Notifications, Feed Notifications, Personal Email, Activity Reminder, Schedule Export |
| PORTAL CONFIGURATION | Configuration, Business Calendar, Project & Budget, Task & Timesheet, Email Notifications, AI Hub |
| PROJECT CONFIGURATION | Task Settings |
| CUSTOMIZATION | Modules and Tabs, Layouts, Fields, Layout Rules, Task Templates, Invitation Templates |
| AUTOMATION | Workflow Rules, Task Blueprint, Email Templates, Email Alerts, Webhooks, Macro Rules, Timesheet Approval Rules, Credits |
| ISSUE TRACKER | Configuration, Web To Issues Form, Link Issues, Email Templates, Notifications, Business Rules, Webhooks, SLA |
| MARKETPLACE | All Apps, Zoho Apps, Installed Apps |
| DEVELOPER SPACE | Custom Functions, Schedule Functions, Create Extension, Connections, APIs, Service Hooks, CodeX Scripts, CodeX Credits |
| DATA ADMINISTRATION | Storage, Imports, Backup, Recycle Bin, Audit Log |
| SANDBOX | Sandbox |
| PROFILES AND ROLES | Profiles, Roles |

Запам'ятай принцип: **налаштування порталу діють на всі проєкти**. Якщо в Setup вимкнено функцію,
вона зникає з форм у всіх проєктах одразу — без жодного повідомлення.

### Два ідентифікатори проєкту

У проєкту є **ID** — наприклад, `TE-1`. Префікс задається для всього порталу в
**Setup → Portal Configuration → Project & Budget**, вкладка **Project & Project Groups**, розділ
**Prefix & ID**: до 10 символів, лише літери й цифри (так пише сам продукт; стаття довідки 2024 року
дозволяє ще й дефіс).

А ще в проєкту є **префікс задач і issues** — наприклад, `QT1`. Його Zoho генерує з назви проєкту,
і з нього складаються ID задач: `QT1-T1`, `QT1-T2`. У панелі деталей проєкту це поле підписане
**Project Prefix** (довідка і старі інструкції звуть його Task & Issues Prefix); змінити його можна
там само, редагуючи проєкт. Назва збігається з портальним налаштуванням, тож дивись, де ти: у Setup
**Project Prefix** — це `TE` для ID проєктів, у панелі проєкту — префікс задач на кшталт `QT1`.

Це **два різні поля**. `TE-1` ідентифікує проєкт, `QT1` — задачі й issues всередині нього.
Порівнювати їх між собою як «одне значення на двох екранах» — помилка аналізу, а не дефект
продукту.

## 2.2. Список проєктів

**Projects** у лівому меню відкриває список проєктів — вид за замовчуванням.

**Що побачиш у тріалі:**

- вкладки **Active Projects | Project Templates | Project Groups | Public Projects | Archived
  Projects**. Вкладки Trash немає: проєкти, видалені в кошик, лежать у
  **Setup → Data Administration → Recycle Bin**;
- кнопки **List** (випадний список виду: **List** або **Gantt**), **Automation** (правила
  автоматизації для проєктів), **New Project**, значок фільтрів і **•••** (More Actions: **Project
  Timeline ICS**, **Export Projects**);
- випадний список видів: **Favorite Views**, **Predefined Views** (All Projects, Recently
  accessed projects, Completed Projects, View by Group, View by Owner, View by Customer),
  **Custom Views** і **+ Create Custom View**.

Що вміє список (документ і довідка Zoho):

| дія | як |
|---|---|
| сортувати й фільтрувати | за статусом, бюджетом, типом білінгу, кастомними полями |
| редагувати на місці | клік по полю в рядку — зміна зберігається одразу |
| дії з проєктом | наведи курсор на рядок → значок **•••** або правий клік: **Edit Project**, **Move to Archive**, **Trash**, **Create Template** та інше |
| експорт | **•••** угорі праворуч → **Export Projects** → **Format** xlsx або csv → **Select Columns** → **Export** |
| колонки | значок **+** (**Add Column**) у кінці рядка заголовків → **+Add** біля поля; правий клік по заголовку → **Hide Column** (там же **Insert Column Before/After**); порядок колонок документ теж дозволяє змінювати |
| бюджет | якщо бюджет увімкнено: колонки плану й факту (Hours Remaining або Cost Variance) і фільтри «під ризиком», «перевищено», «профіцит» |

Ще одна деталь з довідки, корисна для негативних тестів: поле **Billing Method** не можна
змінити, якщо за проєктом уже виставлено рахунок. У тріалі без Zoho Books чи Zoho Invoice цей
випадок не відтворити, але в клієнтському порталі з фінансовою інтеграцією — легко.

## 2.3. Створення проєкту: Template Gallery і форма

Проєкт створюють з нуля або з шаблону.

**Крок перший — Template Gallery.** **Projects → New Project** відкриває панель **Template
Gallery**: картка **Blank project** (з нуля; на ній кнопка **+ New Project**), **Predefined Project
Templates** (готові шаблони Zoho) і вкладка **Project Templates** (шаблони, створені в твоєму
порталі). Документ пояснює, навіщо
шаблони компанії: коли повторюються схожі впровадження (налаштування CRM, автоматизація Desk),
шаблон копіює всі фази, списки задач і структуру, зсуваючи дати від старту нового проєкту.

У галереї є прапорець **Do not show this again**, а внизу форми проєкту — посилання **Browse
Templates** (у тріалі обидва на місці). За довідкою, з цим прапорцем **New Project**
надалі відкриває одразу форму, а до галереї повертаються через **Browse Templates**. Якщо в тебе
галерея «зникла» — причина, найімовірніше, ця.

**Крок другий — форма.** Після **+ New Project** на картці **Blank project** відкривається форма
нового проєкту. У тріалі на ній такі поля:

| поле | що це і на що впливає |
|---|---|
| **Project Title** | назва; обов'язкове |
| **Owner** | власник проєкту |
| **Template** | шаблон, з якого скопіювати структуру (можна вибрати й тут) |
| **Start Date / End Date** | рамки проєкту; без них проєкт не з'явиться на Gantt проєктів |
| **Make this a strict project** | суворий проєкт: фіксовані рамки для всіх дат (розділ 2.6) |
| **Project Group** (+ Add new group) | папка для групування проєктів |
| **Description** | опис проєкту (саме Description, поля Overview немає) |
| **Business Hours** | робочий графік проєкту; обов'язкове (у тріалі одразу підставлено `Standard Business Hours`); за довідкою, за ним рахуються тривалість і робочі години задач без виконавця |
| **Task Layout** | форма задачі: які поля й статуси мають задачі цього проєкту |
| **Tags** | мітки для пошуку й фільтрів |
| **Budget**: Currency, Budget Type, Billing Method | лише після ввімкнення Project Budget (розділ 2.4) |
| кастомна секція | кастомні поля проєкту, якщо їх створено |
| **Roll-up** | за підказкою на формі — дати підтягуються із задач і підзадач у фази й проєкт, а робочі години, записи часу й % виконання — з підзадач у задачі (плани Premium і Enterprise) |
| **Customize tabs for this project** | які вкладки буде в проєкті: Dashboard, Tasks, Users, Reports, Documents, Phases, Time Logs, Finance, Expense Claims, Bugs, Feed, Forums, Pages, Timesheet; за замовчуванням зняті Finance, Expense Claims, Forums і Pages |
| **Project Access** | **Private** або **Public** (розділ 2.5) |

Кнопка створення — **Add**.

### Task Layout і приватна копія

**Layout задачі** — це форма, за якою створюються задачі: набір полів і, що важливо, **список
статусів**. У порталі є **Standard Layout**. Унизу випадного списку **Task Layout** стоїть
прапорець **Create a private copy of this layout**, і за замовчуванням він поставлений: портал
створює **приватну копію** layout для цього проєкту. У тріалі копія зазвичай отримує назву проєкту
(у проєкту з готового шаблону — ID і назву шаблону, наприклад `TE-9 Software Development`, і після
перейменування проєкту назва layout не змінюється), тож надійніше шукати її за підписом
**Associated Projects** під layout на сторінці layouts. Керує цим перемикач
**Make private layouts as a default for all the new projects** на сторінці layouts (у тріалі
увімкнений), тож кожен проєкт має власну приватну копію layout.

Наслідки, які знадобляться весь курс:

- статуси й поля, які ти змінюєш у приватній копії, діють **лише в цьому проєкті**;
- правка **Standard Layout** на проєкт із приватною копією **не впливає**;
- автоматизація задач (Blueprint, Workflow Rules, Email Alerts тощо) прив'язується до layout, тож
  для цього проєкту її треба прив'язувати до його приватної копії.

Знайти, який layout у проєкту: **Setup → Customization → Layouts → вкладка Task** — під кожним
layout показано назви пов'язаних проєктів.

### Проєкти, які народжуються з CRM

Документ попереджає: майже всі проєкти компанії створюються з Zoho CRM за процесом продажів —
коли угода закрита як виграна і клієнт заплатив (або хоча б прийняв пропозицію на Upwork), відділ
продажів запускає створення проєкту. Інструмент для цього в Zoho є: за довідкою Zoho CRM, після
інтеграції CRM з Projects проєкти створюють і пов'язують із записами Accounts, Contacts і Deals
прямо з CRM. Для тебе як QA це означає: ручне створення, яке ти вивчаєш, — не єдина точка входу.
Проєкт, що прийшов з CRM, варто перевіряти на ті самі властивості: шаблон, власник, layout,
доступ, дати.

## 2.4. Бюджет і Billing Method

У новому порталі блоку **Budget** на формі проєкту **немає**. Він з'являється після перемикача:
**Setup → Portal Configuration → Project & Budget → Budget Settings → Enable Project Budget**.
Після ввімкнення на формі з'являються **Currency**, **Budget Type** і **Billing Method**.

**Budget Type** (довідка Zoho) — як задається бюджет:

| тип | що задаєш |
|---|---|
| Based on Project | бюджет і години на весь проєкт |
| Based on Phase | бюджет і години на кожну фазу; бюджет проєкту — їхня сума |
| Based on Task | бюджет і години на кожну задачу |
| Based on User | бюджет і години на кожного учасника |
| None | без бюджету |

**Billing Method** (довідка Zoho) — як рахується вартість роботи для клієнта:

| метод | суть |
|---|---|
| **Based on Staff Hours** | у кожного учасника своя ставка; вартість = години × ставка людини |
| **Based on Project Hours** | одна ставка на проєкт; вартість = усі години × ставка проєкту |
| Fixed Cost for Project | фіксована сума; лише для порталів, інтегрованих із Zoho Invoice або Books (у тріалі його в списку немає) |
| Based on Task/Issue Hours | ставка задається в кожній задачі чи issue |

Документ згадує саме перші два: «staff hours or project hours».

Ще кілька фактів з довідки: бюджет є в планах Premium, Enterprise, Ultimate і доступний
користувачам Zoho One; для профілів адміністраторів бюджет увімкнено одразу, іншим профілям його
дають у налаштуваннях профілів; поруч у Budget Settings — **Include non-billable hours** і листи
про поріг і перевищення бюджету.

**Розбіжність довідки з тріалом.** Кілька статей довідки пишуть, що Billing Method з'являється
лише за інтеграції з Zoho Invoice або Zoho Books. У тріалі поле з'явилося одразу після **Enable
Project Budget**, без жодної фінансової інтеграції. Орієнтуйся на те, що бачиш у продукті, а
розбіжність запиши — такі речі потрапляють у звіт.

**Навіщо це QA.** Це хрестоматійний приклад: портальний перемикач прибирає з форми цілий блок
полів — без помилки, без підказки. Правило перевірки відсутнього поля: **план → права профілю →
перемикач порталу** — і лише потім «дефект» чи «розбіжність з документацією».

## 2.5. Публічні й приватні проєкти

Поле **Project Access** на формі має два значення:

- **Public** — проєкт бачать усі користувачі порталу. За довідкою, ті, хто не є учасниками,
  мають доступ лише на читання: можуть переглядати, стежити (follow) і коментувати. Адміністратор
  порталу має повний доступ навіть до публічних проєктів;
- **Private** — проєкт доступний лише його учасникам.

Публічні проєкти зібрані на вкладці **Public Projects** списку проєктів.

**Як довести, що проєкт приватний.** Панель деталей проєкту (**View** біля назви або **••• → Edit
Project**) праворуч показує **Project Access** з позначеним **Private** чи **Public** — але це лише
налаштування. Доказ поведінки в тріалі — від протилежного: відкрий вкладку **Public Projects**;
приватного проєкту там немає. Повна перевірка — увійти під користувачем порталу, який не є
учасником проєкту, і переконатися, що він проєкту не бачить. Для цього потрібен другий
користувач: у Zoho One його додають в **Admin Panel → User Management → Users → Add User** і
призначають йому Zoho Projects.

## 2.6. Суворі проєкти

Документ: суворі проєкти (strict projects) компанія використовує для високопріоритетних робіт із
жорстким дедлайном — запуск продукту, здача мобільного застосунку. У них:

- обов'язкові дати початку й кінця;
- задачі й фази не можна запланувати поза датами проєкту;
- чітка, непорушна структура графіку.

Вмикається прапорцем **Make this a strict project** на формі. Деталі з довідки Zoho (функція планів
Premium і Enterprise; у тріалі прапорець на формі є):

- фази мають вкладатися в дати проєкту, задачі — у дати фаз і так далі;
- у календарях вибору дат дні за межами графіку просто недоступні, а на неправильний діапазон
  з'являється повідомлення про помилку (у тріалі на дату задачі поза рамками:
  `The selected dates fall outside the project schedule. Please select another date.`);
- **суворий проєкт не може починатися й закінчуватися в один день** — так пише довідка; у тріалі
  форма приймає суворий проєкт з однаковими Start Date і End Date без жодного
  повідомлення, і так само приймає таку зміну дат у вже створеному суворому проєкті;
- у списку проєктів суворий проєкт позначений окремим значком (підказка **Strict Project**).

І список винятків — тут суворість **не діє** (довідка Zoho):

- таймери не зупиняються автоматично після дати кінця проєкту;
- тривалість зустрічей і залогованих годин не обмежена датами проєкту;
- SLA для bugs не прив'язаний до дати кінця проєкту;
- витрати можна додавати й після дати кінця;
- **при імпорті задач чи bugs дати можуть вийти за рамки проєкту**;
- задачі й bugs можна пов'язувати з фазами з іншими датами;
- bugs, пов'язані з фазами, враховують лише дати Release Phase;
- повторення задач і подій та задачі з шаблону задач автоматично підганяються під дати проєкту.

Для QA цей список — готова карта ризиків: кожен виняток — шлях, яким дата може «втекти» за рамки
суворого проєкту. Вимоги клієнта про жорсткий дедлайн треба перевіряти не лише через форму, а й
через імпорт, таймер, лог годин.

## 2.7. Ключові можливості одним поглядом

Документ зводить можливості Projects у таблицю. Ось вона з адресами в тріалі:

| можливість | що дає (за документом) | де в тріалі |
|---|---|---|
| Kanban Boards | задачі візуально за статусом, пріоритетом чи власником | проєкт → **Tasks** → перемикач виду → Kanban |
| Time Tracking | billable і non-billable години прямо в задачах | вкладка **Time Logs**, таймер і лог годин у задачі |
| Phases (раніше Milestones) | чіткі етапи й результати | вкладка **Phases** |
| Task Layouts | поля й статуси під тип проєкту | **Setup → Customization → Layouts → Task** |
| Budget Tracking | витрати, години, ресурси | **Setup → Portal Configuration → Project & Budget → Budget Settings**, блок Budget проєкту |
| Project Templates | стандартизація повторюваних проєктів (налаштування CRM, конфігурація Desk) | **Projects → Project Templates**, Template Gallery |
| Email Integration | створення й оновлення задач та issues листом | поштові адреси (email aliases) в деталях об'єктів |
| Custom Views & Filters | фокус на потрібних задачах і проєктах | випадний список видів → **+ Create Custom View** |

Документ підсумовує: Projects для компанії — не просто трекер задач, а платформа для планування,
координації, обліку часу і звітності.

## 2.8. Перед стартом: налаштування порталу

Документ описує портал, де потрібні функції вже ввімкнено. Свіжий портал приходить із вимкненими.
Тому до практичних завдань налаштуй чотири речі.

**1. Project Budget.** **Setup → Portal Configuration → Project & Budget → Budget Settings →
Enable Project Budget.** Без цього на формі проєкту немає **Billing Method** — і перше ж завдання
невиконуване. У тріалі перемикач уже ввімкнено.

**2. Project Group Prefix.** **Setup → Portal Configuration → Project & Budget → Project &
Project Groups**, перемикач **Project Group Prefix**. Без нього у формі групи проєктів немає поля
префікса; з ним форма **New Group** (вкладка **Project Groups**) має поля **Project Group** і
**Group Prefix** (до 10 символів). У тріалі перемикач уже ввімкнено. Що робить префікс групи:
**замінює портальний префікс в ID проєкту** — наприклад, `TE-2` стає `QAINT-2`; назва проєкту не
змінюється.

**3. Pages і Forums.** Постав їм галочки в **Customize tabs for this project**, коли створюєш
проєкт (за замовчуванням вони зняті). Забув — додаси пізніше: у проєкті **•••** (More Tabs) →
**Add Module/ Web Tab** → у списку **Active Modules** біля **Pages** чи **Forums** — **Add**. Після цього
з'являється повідомлення `Module Added.`, вкладка Pages стає поруч з іншими, а сторінка HomePage
створюється автоматично.

**4. Назви.** Milestones тепер Phases. Модуль Issues у **Customize tabs for this project**
називається **Bugs**.

Що легко відкотити: перемикачі в Setup вмикаються й вимикаються тим самим місцем. Але пам'ятай, що
вони діють на **весь портал** — вимкнений бюджет прибере поля в усіх проєктах.

## 2.9. Покроково: Assignment 1 — Create a Project from Scratch

**Мета завдання:** навчитися вручну створювати проєкт, заповнювати ключові поля й налаштування.

### Підготовка: увімкни бюджет

1. Шестерня у верхньому правому куті → **Portal Configuration → Project & Budget**.
2. Вкладка **Budget Settings** → увімкни **Enable Project Budget**.

**Що побачиш:** перемикач увімкнено (якщо він уже був увімкнений раніше — тоді нічого не
міняй). Перевірка результату — на формі проєкту в кроці 3: там має бути блок **Budget**.

### Створення проєкту

**Крок 1.** Переконайся, що ти в Zoho Projects тріалу (One Bar → Projects).

**Крок 2.** **Projects → New Project** → у Template Gallery на картці **Blank project** натисни
**+ New Project**.

**Що побачиш:** форму нового проєкту з полями з таблиці 2.3.

**Крок 3.** Заповни форму:

| поле | значення |
|---|---|
| **Project Title** | `QA Training Project – <твоє ім'я>`, наприклад `QA Training Project – Olena Kovalenko` |
| **Owner** | ти сам |
| **Start Date** | сьогодні |
| **End Date** | сьогодні + 7 днів (формат дат порталу — dd-MM-yyyy: якщо сьогодні `26-09-2026`, то `03-10-2026`) |
| **Description** | `This is a training project created as part of the onboarding process.` |
| **Task Layout** | будь-який стандартний layout зі списку, наприклад **Standard Layout**; опцію приватної копії лиши як є |
| **Budget → Billing Method** | **Based on Project Hours** |
| **Budget Type** | можна лишити **None** — завдання вимагає лише методу білінгу |
| **Customize tabs for this project** | додатково постав **Pages** і **Forums** — знадобляться пізніше |
| **Project Access** | **Private** |

Решту полів (Template, Project Group, Tags, Roll-up, strict) не чіпай — завдання їх не вимагає.
**Business Hours** обов'язкове, але в тріалі вже підставлене (`Standard Business Hours`) — лиши
його. Дати вибираєш у
календарі; у календарі **End Date** дні раніше за **Start Date** недоступні. З **Budget Type** =
**None** і **Based on Project Hours** ставок форма в тріалі не просить; якщо з іншим типом бюджету
з'являться поля ставок (наприклад, **Cost Per Hour**), введи умовні числа.

Якщо в порталі вже є проєкт із такою самою назвою (наприклад, з попередньої спроби), не видаляй
його — додай до нової назви уточнення або заархівуй старий, щоб у звіті не було двозначності.

**Крок 4.** Натисни **Add**.

**Що побачиш:** одразу відкривається новий проєкт на вкладці **Tasks** (вид List, поки без
задач); у заголовку — ID вигляду `TE-<номер>` і назва (у цьому порталі портальний префікс — `TE`,
номер видається по порядку, наприклад `TE-6`). У списку **Active Projects** він теж з'являється — з
датами й методом білінгу.

### Перевірка

**Крок 5.** Відкрий проєкт і його панель деталей (у заголовку проєкту — **View** поруч із назвою
або **•••** → **Edit Project**). Звір: назва, власник, дати, Description, у блоці Budget —
`Billing Method = Based on Project Hours`, праворуч — **Project Access: Private**. Там само
побачиш поле **Project Prefix** — префікс майбутніх задач (для такої назви на кшталт `QT1`).

**Крок 6.** Доведи приватність: **Projects → Public Projects** — твого проєкту там немає (якщо
публічних проєктів у порталі немає взагалі, вкладка покаже `No projects found`).

**Крок 7.** Подивись на layout: **Setup → Customization → Layouts → вкладка Task**. Знайди layout,
під яким вказано твій проєкт, — це його приватна копія.

**Крок 8.** Скопіюй URL проєкту з адресного рядка (вигляд
`https://projects.zoho.eu/portal/<портал>#zp/projects/<id>/`).

### Deliverable

Скриншот створеного проєкту і URL (або зображення). Практично зручно здати:

1. скриншот панелі деталей: назва, власник, дати, Description;
2. скриншот блоку Budget з **Billing Method = Based on Project Hours**;
3. URL проєкту;
4. як доказ приватності — скриншот вкладки **Public Projects** без твого проєкту і панелі
   деталей з **Project Access: Private** (необов'язково, але знімає питання).

Що відкотити легко: будь-яке поле проєкту редагується пізніше через **Edit Project** або прямо в
списку. Що не відкотиш так само просто: зміни в Setup діють на весь портал.

## 2.10. Як це тестувати

### Що може зламатися у створенні проєкту

| зона | ризик | перевірки |
|---|---|---|
| обов'язкові поля | проєкт створюється без назви чи без Business Hours | порожня назва, лише пробіли, дуже довга назва (зафіксуй фактичний ліміт) |
| дати | End Date раніше за Start Date; суворий проєкт на один день | обидва варіанти, повідомлення про помилку (у тріалі календар End Date не дає вибрати день раніше за Start Date, а суворий проєкт на один день зберігся без помилки) |
| бюджет | блок Budget є/немає залежно від перемикача | перемикач вимкнено → блоку немає; увімкнено → є |
| Billing Method | метод не зберігся або змінився | зберегти, відкрити заново, звірити |
| доступ | приватний проєкт видно стороннім | вкладка Public Projects; вхід під не-учасником |

| layout | проєкт прив'язано не до того layout | **Setup → Customization → Layouts → Task**, пов'язані проєкти |

| список | експорт не збігається зі списком | експорт у CSV вибраних полів і звірка |

## 2.11. Типові помилки

**1. Шукати Billing Method, не ввімкнувши бюджет.** Блок Budget з'являється лише після **Enable
Project Budget** у Setup.

**2. Шукати поле Overview.** На формі проєкту — **Description**.

**3. Шукати вкладку Trash у списку проєктів.** Її немає: кошик — **Setup → Data Administration →
Recycle Bin**.

**4. Шукати Milestones.** Тепер це **Phases**. А Issues у переліку вкладок — **Bugs**.

**5. Правити Standard Layout і дивуватися, що в проєкті нічого не змінилось.** Проєкт працює на
своїй приватній копії layout.

**6. Не поставити Pages і Forums при створенні — і вирішити, що проєкт треба перестворювати.** Не
треба: **•••** → **Add Module/ Web Tab**.

**7. Порівнювати ID проєкту з префіксом задач.** `TE-1` і `QT1` — різні поля з різних налаштувань.

**8. Вважати позначку Private у панелі деталей доказом приватності.** **Project Access** показує
налаштування, а не те, що бачать інші; доказ — вкладка **Public Projects** або вхід іншого
користувача.

**9. Вимкнути портальний перемикач «для тесту» у спільному порталі.** Поля зникнуть у всіх
проєктах. У клієнтському порталі такі кроки узгоджують заздалегідь.

### Симптом → причина

| симптом | найімовірніша причина |
|---|---|
| на формі проєкту немає блоку Budget і Billing Method | вимкнено **Enable Project Budget** |
| у формі групи проєктів немає поля префікса | вимкнено **Project Group Prefix** |
| **New Project** одразу відкриває форму, без галереї | колись поставили **Do not show this again**; галерея — кнопкою **Browse Templates** |
| у проєкті немає вкладок Pages чи Forums | не поставили їх у **Customize tabs**; додай через **•••** → **Add Module/ Web Tab** |
| у проєкті не знайти Issues | вкладка схована під **•••** (More Tabs); у переліку вкладок вона звалась Bugs |
| зміни статусів у Standard Layout не видно в проєкті | проєкт прив'язаний до приватної копії layout |
| проєкт не видно на вкладці Public Projects | він приватний (очікувано) |
| проєкту немає на Gantt проєктів | у нього не задано Start Date або End Date |
| у суворому проєкті не вибирається потрібна дата | дата поза рамками проєкту чи фази |
| `The selected dates fall outside the project schedule. Please select another date.` | дата задачі поза рамками суворого проєкту |
| суворий проєкт з однаковими датами зберігається без помилки | так поводиться тріал, хоча довідка це забороняє; фіксуй як розбіжність |
| ID проєкту `TE-1`, а задачі `QT1-T1` | це два різні ідентифікатори: портальний префікс і префікс задач проєкту |
| у панелі проєкту **Project Prefix** = `QT1`, а не `TE` | це префікс задач цього проєкту; портальний префікс ID живе в Setup під тією ж назвою |
| Billing Method не редагується | за проєктом уже виставлено рахунок (за довідкою) |

## 2.12. Що варто запам'ятати

1. Портал — простір Projects організації; Setup (шестерня) діє на всі проєкти одразу.
2. Структура: Project → Phase → Task List → Task → Subtask; окремо Issues і Time Logs.
3. Milestones тепер Phases; Issues у переліку вкладок — Bugs.
4. **New Project** відкриває Template Gallery: Blank project, Predefined Project Templates,
   Project Templates.
5. Поле опису — **Description**; обов'язкові — **Project Title** і **Business Hours**.
6. Блок Budget і **Billing Method** з'являються лише після **Enable Project Budget**.
7. Кожен проєкт у тріалі отримує приватну копію task layout; статуси й автоматизацію налаштовують
   саме в ній.
8. Public — читання для всіх користувачів порталу; Private — лише учасники; приватність доводиш
   вкладкою **Public Projects** або входом не-учасника.
9. Суворий проєкт тримає всі дати в рамках, але має винятки: імпорт, таймери, лог годин, витрати.
   Заборону проєкту на один день описує довідка, а тріал її не застосовує.
10. ID проєкту (`TE-1`) і префікс задач (`QT1`, поле **Project Prefix** у панелі проєкту) — різні
    ідентифікатори.
11. Перед практикою: Project Budget, Project Group Prefix, Pages і Forums у вкладках.
12. Відсутнє поле перевіряй за ланцюжком: план → права → перемикач порталу.

запиши це: від цього залежить, де ти налаштовуватимеш статуси й автоматизацію.

**2.5.** Колонка додається значком **+** (**Add Column**) у кінці рядка заголовків → **+Add** біля
поля; ховається правим кліком по заголовку → **Hide Column**. Експорт: **•••** угорі праворуч →
**Export Projects** → **Format** csv → **Select Columns** → **Export**. У файлі мають бути ті самі
проєкти й значення, що в списку (зверни увагу на формат дат і на порожні значення).

У клієнтському порталі перед здачею перевіряв би: чи експорт містить усі проєкти поточного виду і
лише їх; чи збігаються значення (особливо дати, валюта, числа бюджету); чи кирилиця й спецсимволи
в назвах не зіпсувались у файлі; чи сховані колонки не «прилипають» до експорту.

**2.6.**

| хто | Public | Private |
|---|---|---|
| адміністратор порталу, не учасник | повний доступ | за довідкою, адміністратор має всі права навіть у публічних проєктах; доступ до приватних перевір у своєму порталі окремо |
| користувач порталу, не учасник | бачить проєкт, читає, стежить (follow), коментує; не редагує | проєкту не бачить |
| учасник проєкту | працює відповідно до своєї ролі в проєкті | працює відповідно до своєї ролі в проєкті |

Чесна примітка до другого рядка Private для адміністратора: довідка прямо описує повний доступ
адміністратора до публічних проєктів; про приватні — не пише. Такі «білі плями» в тест-плані
позначають як «перевірити», а не заповнюють припущенням.

**2.7.**

- а) Не вийде: у суворому проєкті вибір дат не пропонує дні поза рамками, а на неправильний
  діапазон з'являється помилка.
- б) За довідкою, при імпорті дати можуть вийти за рамки — задача, найімовірніше, імпортується з
  датою поза проєктом. Це задокументований виняток і хороший тест.
- в) За довідкою не збережеться: суворий проєкт не може починатися й закінчуватися в один день.
  У тріалі такий проєкт зберігається без жодного повідомлення — передбачення з довідки
  треба перевіряти в продукті, а розбіжність записати.
- г) Таймер працюватиме далі: таймери не зупиняються автоматично після дати кінця проєкту.
- д) Витрату можна додати: витрати дозволені й після дати кінця.

**2.8.**

- а) Спершу ланцюжок план → права → перемикач. Тут перемикач: **Enable Project Budget**. Не баг, а
  тим більше не Critical.
- б) Проєкт прив'язаний до своєї приватної копії layout; правка Standard Layout на нього не
  впливає. Не дефект.
- в) Це два різні ідентифікатори: ID проєкту з **Prefix & ID** і префікс задач та issues,
  згенерований з назви. Порівнювати їх некоректно.
- г) **Project Access: Private** у панелі деталей — це налаштування, а не доказ того, що сторонні
  проєкту не бачать. Доказ — вкладка **Public Projects** або вхід не-учасника.
- д) Не треба: **•••** (More Tabs) → **Add Module/ Web Tab** → **Pages**.

**2.9.** Очікуваний результат: (а) суворий проєкт з однаковими Start Date і End Date
зберігається без жодного повідомлення — і при створенні, і при зміні End Date у панелі деталей
(`Project updated`), хоча довідка це забороняє: запиши як розбіжність; (б) у календарі Due Date
дні поза рамками проєкту недоступні, а вручну введена дата після кінця проєкту на **Add** дає
`The selected dates fall outside the project schedule. Please select another date.` і кнопку
**OK**, задача не зберігається. Відповідь на питання: так, дні поза графіком у календарі
недоступні. Якщо твій результат інший — фіксуй зі скриншотом. Проєкт після експерименту можна
лишити або перенести в архів (**Move to Archive** у меню рядка).

|---|---|---|

**2.11.**

- а) ID проєкту (`TE-1`) — ідентифікатор проєкту в порталі; префікс задається в **Prefix & ID** (до
  10 символів) і може бути замінений префіксом групи. **Project Prefix** у панелі проєкту (`QT1`;
  у довідці — Task & Issues Prefix) — префікс ID задач та issues всередині проєкту (`QT1-T1`),
  генерується з назви проєкту, редагується в проєкті.
- б) Standard Layout — стандартний layout порталу. Приватна копія — окремий layout, створений для
  одного проєкту; зміни в ній діють лише там, а зміни в Standard Layout на неї не переходять.
- в) Archived Projects — вкладка списку: проєкт на місці, його можна розархівувати однією дією.
  Recycle Bin — **Setup → Data Administration → Recycle Bin**: проєкт видалено в кошик, його можна
  відновити протягом строку зберігання, після якого він зникає назавжди.
